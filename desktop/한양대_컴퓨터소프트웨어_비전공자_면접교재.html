01. 프로그램과 C의 첫 실행

소스 코드·컴파일·실행을 구분하고, 첫 프로그램의 각 줄을 읽는다. 선수 지식은 없다.

코드는 컴퓨터가 할 일을 적은 글이다

소스 파일은 명령을 적은 텍스트다. C 컴파일러는 전처리와 번역을 거쳐 목적 코드를 만들고, 링커는 필요한 코드와 연결해 실행 파일을 만든다. 실행 파일을 실제로 시작하면 운영체제가 프로세스로 실행한다. ‘컴파일에 성공했다’는 문법과 일부 규칙 검사를 통과했다는 뜻이지, 의도대로 동작한다는 보장은 아니다.

#include <stdio.h>

int main(void) {
    printf("Hello, C!\n");
    return 0;
}

#include <stdio.h>는 표준 입출력 함수의 선언을 이용하게 한다. 여기서 #는 주석이 아니다. main은 일반적인 실행 환경의 시작 함수다. 괄호의 void는 이 형태에서 매개변수가 없다는 뜻이다. 중괄호는 여러 문장을 묶고, 세미콜론은 문장을 끝낸다. printf는 문자열을 출력한다. \n은 줄바꿈이다. return 0;은 운영 환경에 성공 종료를 알린다.

읽기 → 예측 → 실행 → 이유 설명

위 코드를 UTF-8 텍스트 hello.c로 저장한다. GCC가 설치된 터미널에서는 gcc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello.exe, Windows PowerShell에서는 이어서 .\hello.exe로 실행할 수 있다. 컴파일러는 위젯용 Python과 별개다. 이 교재는 C17 기준으로 설명하되 기초 예제는 C11과 공통인 문법을 사용한다. 특정 IDE나 유료 도구는 필요하지 않다.

터미널에 명령을 입력하는 것과 C 파일에 코드를 작성하는 것을 구분한다. // 설명은 줄 끝까지의 주석, /* 설명 */은 구간 주석이다. 들여쓰기는 사람이 흐름을 읽기 위한 것으로, C의 블록은 들여쓰기 자체가 아니라 중괄호로 정해진다.

문제 풀기

Hello를 두 줄 출력하려면 무엇을 바꾸고, return 뒤의 출력은 실행될까?

printf 문장을 return 앞에 두 번 쓰거나 문자열에 줄바꿈을 넣는다. 실행 흐름이 return에 도달하면 그 함수가 끝나므로 그 뒤에 순서대로 놓인 출력문은 실행되지 않는다.

면접 준비

C 소스는 컴파일과 링크를 거쳐 실행 파일이 되고, 실행 중인 프로그램은 프로세스입니다. main에서 문장이 순서대로 실행되며 printf는 출력, return은 함수 종료와 결과 전달을 담당합니다.
컴파일 오류와 논리 오류는 어떻게 다른가?

세미콜론 누락처럼 번역을 막는 문제와, 합계를 구해야 하는데 곱셈을 한 것처럼 실행은 되지만 의도가 틀린 문제는 다르다. 경고도 살피고 작은 입력의 기대 결과를 미리 정해야 한다.

02. 자료형과 변수 — 어떤 값을 담는가

값·변수·자료형을 구분하고 초기화, 정수 나눗셈, 출력 형식을 설명한다. 먼저 첫 실행을 마친다.

변수는 저장된 값을 이름으로 다루는 수단이다. int age = 25;에서 int는 자료형, age는 이름, 25는 초기값이다. 자료형은 값의 표현과 가능한 연산을 정한다. 선언은 이름과 형식을 알리고, 초기화는 객체가 만들어질 때 첫 값을 준다. 나중의 age = 26;은 대입이다.

형식용도와 예주의
int정수 개수, int count = 3;크기를 무조건 4바이트로 외우지 않는다.
unsigned int음수가 아닌 정수, 5u범위를 벗어난 연산은 모듈러 규칙을 따른다.
double실수 근삿값, 3.5모든 소수를 정확히 표현하지 못한다.
char문자 코드 한 단위, 'A'한글 한 글자가 char 하나라는 뜻은 아니다.
bool참·거짓, true/falseC17에서는 stdbool.h를 포함한다.
#include <stdio.h>
int main(void) {
    int count = 3;
    double price = 2.5;
    char grade = 'A';
    printf("%d %.1f %c\n", count, price, grade);
    printf("%d %.1f\n", 5 / 2, 5 / 2.0);
    printf("%zu\n", sizeof count);
    return 0;
}

첫 줄은 3 2.5 A, 다음은 2 2.5다. 정수끼리 나누면 정수 몫이 된다. 마지막 출력은 현재 구현의 int 크기라 환경에 따라 다를 수 있다. sizeof의 결과는 size_t라서 %zu로 출력한다. printf의 %d는 int, %u는 unsigned int, %f는 double, %c는 문자를 출력하는 약속이다. 인자 형식이 약속과 맞아야 한다.

비트는 0 또는 1이고, C에서 sizeof(char)는 항상 1이다. 한 바이트의 비트 수는 CHAR_BIT로 확인하며 흔한 환경에서는 8이다. 자료형의 한계는 limits.h 등을 확인한다. 초기화하지 않은 자동 지역 변수의 값을 읽으면 안전하게 0이 나오는 것이 아니다. 처음부터 값을 정하자. const int limit = 10;은 해당 이름을 통한 수정을 금지한다.

문제 풀기

double x = 5 / 2;에서 x가 2.5가 아닌 이유는?

오른쪽에서 정수 나눗셈이 먼저 이루어져 2가 나온 뒤 double의 2.0으로 변환된다. 5.0 / 2 또는 (double)5 / 2로 나눗셈 전에 실수 연산이 되게 한다.

면접 준비

자료형은 값의 표현 범위와 연산 규칙을 정합니다. int와 double은 나눗셈 결과부터 다를 수 있고, 정수 크기는 구현에 의존하므로 sizeof와 표준 한계값으로 확인합니다. 지역 변수는 사용 전에 초기화하겠습니다.
int가 항상 32비트인가? 실수 비교도 정수처럼 생각해도 되나?

아니다. int의 크기와 범위는 구현을 확인한다. 부동소수점은 근삿값이므로 계산 결과의 비교에서는 문제의 단위와 오차 허용 범위를 따져야 한다.

03. 대입·산술·증감 연산자

각 문장 후 변수 값을 표로 적고, 전위·후위 증감의 차이를 설명한다.

=는 등식이 아니라 오른쪽 결과를 왼쪽 객체에 저장하는 연산이다. x = x + 2;는 이전 값을 읽어 2를 더하고 다시 저장한다. 산술 연산자는 +, -, *, /, %다. 정수 나눗셈은 0 쪽으로 잘리며 %는 정수 나머지다. 0으로 나누거나 나머지를 구하면 안 된다.

#include <stdio.h>
int main(void) {
    int x = 3;
    x += 2;          // x = 5
    int a = x++;     // a = 5, x = 6
    int b = ++x;     // x = 7, b = 7
    x--;             // x = 6
    printf("%d %d %d\n", x, a, b);
    return 0;
}

출력은 6 5 7이다. 후위 x++도 x를 증가시킨다. 차이는 그 식이 내놓는 값이 증가 전 값이라는 점이다. 전위 ++x의 식 값은 증가 후 값이다. 증감을 문장 하나로만 쓸 때에는 보통 최종 x가 같지만, 다른 대입 안에서 사용하면 결과가 달라진다. x += 2처럼 복합 대입은 왼쪽을 한 번 평가한다는 특징도 있으므로 복잡한 식에서는 단순한 글자 치환으로 생각하지 않는다.

짧게 쓰는 것보다 평가 순서가 명확해야 한다

i++ + ++i, i = i++ 같은 식은 C에서 한 객체의 수정·접근 사이 순서가 보장되지 않아 정의되지 않은 동작을 일으킨다. 특정 컴파일러가 출력한 숫자를 정답으로 외우지 않는다. printf의 여러 인자도 왼쪽부터 평가된다고 가정하면 안 된다. 부수 효과가 있는 식은 별도 문장으로 나눈다.

곱셈이 덧셈보다 먼저 묶이지만, 헷갈리면 괄호로 의도를 드러낸다. 2 + 3 * 4는 14, (2 + 3) * 4는 20이다. 부호 있는 정수 오버플로는 일반적인 순환을 보장하지 않는다. 예제 입력은 계산 결과가 해당 형식에 들어가는 범위로 제한한다.

문제 풀기

int n=4; int p=n--; int q=--n; 뒤 n,p,q는?

첫 증감 뒤 p=4, n=3. 다음 증감 뒤 n=2, q=2. 따라서 n,p,q는 2,4,2다. 각 선언은 서로 다른 문장이므로 순서가 명확하다.

면접 준비

전위와 후위 증감은 모두 객체를 1 증가시키지만, 식의 결과가 각각 증가 후와 증가 전 값입니다. 한 식에서 같은 변수를 여러 번 수정해 순서에 의존하지 않고 문장을 나누겠습니다.
printf("%d %d", i++, i++)의 결과를 왜 외우면 안 될까?

C에서는 이 두 인자의 평가 사이에 요구되는 순서가 없고 같은 i를 수정하므로 정의되지 않은 동작이다. 각각 별도 문장으로 계산한 뒤 출력해야 한다.

04. 비교·논리 연산과 조건문

조건을 참·거짓으로 계산하고, 논리 AND와 비트 AND를 구분한다.

비교 연산자 ==, !=, <, <=, >, >=의 결과는 int의 0 또는 1이다. 조건에서는 0이 거짓이고 0이 아닌 값은 참이다. if (x == 3)은 비교지만 if (x = 3)은 대입 후 그 값으로 판단한다. 후자는 의도와 달라도 문법적으로 가능한 탓에 경고 확인이 중요하다.

#include <stdio.h>
int main(void) {
    int score = 75;
    int attendance = 1;
    if (score >= 60 && attendance != 0) {
        printf("pass\n");
    } else {
        printf("retry\n");
    }
    int divisor = 0;
    if (divisor != 0 && 10 / divisor > 1) {
        printf("large quotient\n");
    }
    return 0;
}

출력은 pass 한 줄이다. &&는 둘 다 참, ||는 하나라도 참, !는 참·거짓을 뒤집는다. &&는 왼쪽이 거짓이면 오른쪽을 평가하지 않고, ||는 왼쪽이 참이면 오른쪽을 평가하지 않는다. 이것이 단락 평가다. 예제에서 divisor가 0이므로 위험한 나눗셈을 실행하지 않는다.

&와 |는 정수의 비트들을 연산하고 단락 평가하지 않는다. 논리 연산의 짧은 표기법이 아니다. 0 < x < 10도 수학처럼 쓰지 않는다. C에서는 앞 비교 결과 0 또는 1을 10과 다시 비교한다. 0 < x && x < 10이라고 작성한다. else if는 앞 조건이 실패한 뒤 다음 조건을 판단한다. switch는 정수 계열 값의 경우를 나눌 때 쓸 수 있고 break가 없으면 다음 case로 흐를 수 있다.

문제 풀기

2 && 4와 2 & 4는 각각 얼마인가?

2와 4는 둘 다 0이 아니므로 논리 AND는 1이다. 비트로 0010과 0100은 겹치는 1 자리가 없으므로 비트 AND는 0이다.

면접 준비

논리 연산자는 참·거짓을 조합하고 결과는 0 또는 1입니다. AND와 OR의 단락 평가를 이용하면 0으로 나누는 상황처럼 선행 검사가 필요한 연산을 보호할 수 있습니다.
입력값이 15일 때 0 < x < 10이 참이 되는 이유는?

0<15가 1이 되고, 1<10도 참이다. 범위 조건 두 개를 &&로 연결해야 한다.

05. 반복문 — 실행 횟수와 상태 추적

for·while·do while의 순서를 이해하고, 반복 전후의 변화를 직접 적는다.

반복문은 같은 형태의 작업을 여러 번 수행한다. for의 순서는 초기화 1회→조건 검사→본문→증감→조건 검사다. 조건은 본문 전에 평가되므로 처음부터 거짓이면 본문이 한 번도 실행되지 않는다.

#include <stdio.h>
int main(void) {
    int total = 0;
    for (int i = 1; i <= 4; ++i) {
        total += i;
    }
    printf("%d\n", total);
    int n = 8;
    while (n > 1) {
        n /= 2;
        printf("%d ", n);
    }
    return 0;
}
본문 진입 i기존 total새 total
101
213
336
4610

첫 출력은 10이고, while은 8→4→2→1로 바뀌며 4 2 1을 출력한다. 마지막에 n=1이 되면 다음 조건 검사가 거짓이다. 4번 더하는 반복과 3번 반감하는 반복을 비교하면 나중에 O(n)과 O(log n)을 이해하는 기반이 된다.

do while은 본문 뒤에 조건을 검사해서 적어도 한 번 실행한다. break는 가장 안쪽 반복을 끝내고, continue는 이번 본문의 나머지를 건너뛴다. for의 continue는 증감식으로 이동하지만 while은 조건 검사로 이동한다. while에서 증가 코드를 continue 뒤에만 놓으면 반복이 끝나지 않을 수 있다.

배열을 배우면 인덱스는 보통 0 <= i && i < n으로 제한한다. i <= n과 혼동하는 한 칸 오류가 흔하다. 반복마다 무엇이 유지되는지 설명하는 문장을 불변식이라고 한다. 위 합계에서는 ‘다음 i를 더하기 직전 total은 1부터 i−1까지의 합’이 유지된다.

문제 풀기

i=0부터 i<3인 동안 반복하면 본문과 조건 검사는 각각 몇 번인가?

본문은 i=0,1,2에서 세 번, 조건은 i=3에서 실패하는 검사까지 네 번이다. continue나 break가 없는 기본 반복을 가정한다.

면접 준비

for는 초기화·조건·증감을 한곳에 모으고 while은 조건 중심으로 반복합니다. 종료 조건뿐 아니라 반복마다 상태가 종료 방향으로 변하는지 확인하고, 출력 전에 변수 변화를 추적합니다.
2회 반복 안에 3회 반복을 넣으면 작업은 몇 번인가?

안쪽 작업은 2×3=6회다. 2회 반복과 3회 반복을 나란히 실행하면 5회다. 중첩과 순차 실행을 구분한다.

06. 함수와 값 전달

인자·매개변수·반환값을 구분하고, C가 값을 복사해서 전달한다는 뜻을 설명한다.

#include <stdio.h>
int twice(int value) {
    return value * 2;
}
void change(int value) {
    value = 99;
    printf("inside: %d\n", value);
}
int main(void) {
    int x = 3;
    int result = twice(x);
    change(x);
    printf("outside: %d, result: %d\n", x, result);
    return 0;
}

twice의 앞 int는 반환형이다. 괄호 안 int value는 매개변수 선언이다. 호출할 때 넘기는 x의 값 3은 인자다. value는 그 값을 복사받은 별도 객체다. twice는 6을 반환해 result에 저장하게 한다. change는 자신의 value만 99로 바꾸므로 최종 출력은 outside: 3, result: 6이다.

void 반환형은 돌려주는 값이 없다는 뜻이다. 화면에 출력하는 함수와 결과를 반환하는 함수는 다르다. 출력만 하면 다른 계산에 그 결과를 바로 사용할 수 없다. 함수를 호출하기 전에 선언이 보여야 한다. 큰 프로그램에서는 int twice(int value); 같은 함수 원형을 먼저 놓고 정의를 뒤에 둘 수 있다.

아직 포인터를 몰라도 확인할 수 있는 것

여기서는 ‘함수 안의 매개변수를 바꾸면 호출자의 int도 바뀐다’고 생각하지 않는 것이 중요하다. 호출자의 객체를 바꾸는 방법은 포인터 장에서 배운다. 그때에도 C의 전달 방식 자체가 참조 전달로 바뀌는 것은 아니다. 주소를 담은 값이 복사된다.

문제 풀기

int a=4; twice(a);만 실행하면 a는 8이 될까?

a는 4다. 반환된 8을 저장하지 않고 버렸기 때문이다. a=twice(a);로 대입해야 a가 8이 된다.

면접 준비

C는 인자 값을 매개변수에 복사합니다. 매개변수를 다른 값으로 바꿔도 호출자의 정수 변수는 그대로입니다. 반환값은 호출식의 결과이고, printf로 화면에 보여주는 것과는 별개입니다.
함수를 나누면 무엇이 좋아지고 무엇을 조심해야 할까?

역할이 분명해지고 작은 입력으로 따로 검증하기 쉽다. 입력 조건과 반환 의미를 정해야 하며, 함수가 보이지 않는 전역 상태를 너무 많이 바꾸면 결과를 추론하기 어려워진다.

07. 지역변수·전역변수 — 범위와 수명

‘어디서 이름을 쓸 수 있는가’와 ‘객체가 언제까지 존재하는가’를 분리한다.

블록 안에서 선언한 지역변수는 해당 블록 안에서 이름을 사용할 수 있다. 파일 범위에 선언한 변수를 흔히 전역변수라고 부른다. 파일 범위 선언이 뒤 파일이나 선언 전의 모든 코드에서 자동으로 보인다는 뜻은 아니다. 범위(scope), 저장 기간(storage duration), 연결(linkage)은 서로 다른 개념이다.

#include <stdio.h>
int total;                         // 정적 저장 기간, 0으로 초기화
void visit(void) {
    int local = 0;                 // 호출마다 새로 초기화
    static int calls = 0;          // 함수가 끝나도 값 유지
    ++local;
    ++calls;
    ++total;
    printf("%d %d %d\n", local, calls, total);
}
int main(void) {
    visit();
    visit();
    return 0;
}

출력은 첫 호출 1 1 1, 둘째 호출 1 2 2다. local은 호출마다 새로 0이 된다. calls는 이름이 함수 블록 안에만 보이지만 수명은 프로그램 실행 동안 유지된다. total도 프로그램 실행 동안 존재한다. 따라서 ‘지역변수는 무조건 함수 종료 시 사라진다’는 말은 static 지역변수 때문에 정확하지 않다.

일반 자동 지역변수는 초기화하지 않으면 자동으로 0이 되는 보장이 없다. 정적 저장 기간 객체는 명시적 초기화가 없을 때 0에 해당하는 값으로 초기화된다. 파일 범위 static은 다른 번역 단위에서 그 이름으로 직접 연결되지 않게 하는 내부 연결과 관련된다. extern 선언은 다른 곳에 정의된 객체를 지칭할 때 쓰지만 선언과 실제 정의를 구분해야 한다.

지역변수를 ‘스택’, 전역변수를 ‘데이터 영역’에 그리는 것은 흔한 구현을 이해하기 위한 그림이다. C 언어가 모든 자동 변수를 반드시 물리 스택에 배치하라고 정하는 것은 아니다. 안쪽 블록에서 같은 이름을 선언하면 바깥 이름을 가릴 수 있으므로 초보 단계에서는 다른 이름을 권한다.

문제 풀기

visit을 세 번 호출하면 세 번째 출력은? static을 지우면?

1 3 3이다. calls에서 static을 지우면 매번 0에서 시작해 세 번째 출력은 1 1 3이 된다.

면접 준비

지역·전역은 이름이 보이는 범위이고, 자동·정적 저장 기간은 객체의 수명입니다. static 지역변수는 범위는 지역이지만 호출 사이에 값이 유지됩니다. 전역 상태는 공유가 쉽지만 함수 간 의존성과 동시 접근 문제를 늘릴 수 있습니다.
전역변수를 쓰면 편한데 왜 줄이라고 할까?

누가 언제 값을 바꾸는지 추적하기 어렵고, 함수 단독 테스트나 여러 스레드의 동시 접근이 복잡해진다. 필요한 상태를 인자와 반환값으로 드러내면 의존성을 이해하기 쉽다.

08. 비트 표현과 비트 연산

작은 이진수를 읽고, 마스크로 상태 비트를 켜고·끄고·검사한다.

이진수 각 자리는 오른쪽부터 1,2,4,8의 가중치를 갖는다. 0101은 4+1=5, 0011은 2+1=3이다. 아래 4자리 그림은 낮은 네 비트만 보여준다. unsigned int 전체가 4비트라는 뜻은 아니다. C17의 이식 가능한 예제에서는 0b 접두사를 사용하지 않고 십진 정수나 16진수로 쓴다.

연산낮은 4비트 예결과
5u & 3u0101 AND 00110001 = 1
5u | 3u0101 OR 00110111 = 7
5u ^ 3u0101 XOR 00110110 = 6
5u << 1왼쪽으로 한 자리1010 = 10
5u >> 1오른쪽으로 한 자리0010 = 2
#include <stdio.h>
int main(void) {
    unsigned int flags = 0u;
    unsigned int read_mask = 1u << 0;
    unsigned int write_mask = 1u << 1;
    flags |= read_mask;                // 0001
    flags |= write_mask;               // 0011
    printf("%u\n", flags);            // 3
    printf("%d\n", (flags & read_mask) != 0u); // 1
    flags &= ~write_mask;              // 쓰기 비트만 끔
    flags ^= read_mask;                // 읽기 비트를 반전
    printf("%u\n", flags);            // 0
    return 0;
}

OR는 지정 비트를 켜고, AND와 반전 마스크는 지정 비트를 끈다. XOR는 지정 비트를 뒤집는다. ~는 모든 비트를 반전하므로 ~5u를 ‘4자리에서 10’이라고 단정하면 안 된다. 결과는 실제 unsigned int 폭 전체에 걸친다. 부호와 정수 승격 문제를 줄이기 위해 이 장은 unsigned int로 연습한다.

시프트 횟수는 음수이거나 승격된 왼쪽 피연산자 형식의 비트 폭 이상이면 안 된다. 부호 있는 값, 특히 음수의 시프트는 별도 규칙이 있어 ‘무조건 곱셈/나눗셈’으로 외우지 않는다. 작은 unsigned 예에서 관찰한 결과를 모든 int 입력으로 일반화하지 않는다. (flags & mask) != 0u처럼 괄호를 써 비교와 비트 연산의 묶임을 명시한다.

문제 풀기

flags=5u에서 두 번째 비트(1u<<1)를 켜고, 첫 비트를 끄면?

0101 OR 0010은 0111이므로 7. 여기에 ~0001 마스크를 AND하면 낮은 비트가 0110이 되어 6이다. ~는 실제 정수 폭 전체에서 계산된다.

면접 준비

비트 연산은 정수의 각 자리 상태를 조작합니다. 권한 플래그처럼 여러 참·거짓 상태를 한 정수에 담을 때 마스크를 사용하며, 논리 연산과 달리 결과가 항상 0 또는 1인 것은 아닙니다.
!5u와 ~5u는 왜 다른가?

!는 논리 부정이라 0이 아닌 5u를 거짓 값 0으로 바꾼다. ~는 unsigned 값의 모든 비트를 뒤집어 형식의 폭에 따른 다른 정수를 만든다.

09. 배열과 문자열 — 같은 자료형을 순서대로

배열 길이와 인덱스를 구분하고, 반복문으로 원소를 안전하게 방문한다.

배열은 같은 자료형의 원소를 연속해서 저장한다. int a[3]에는 int 세 개가 들어가며 인덱스는 0,1,2다. a[3]은 마지막 원소가 아니라 범위 밖이다. C가 자동으로 범위를 검사해 주지는 않으므로 프로그램이 길이를 관리해야 한다.

#include <stdio.h>
int main(void) {
    int scores[] = {70, 80, 90};
    size_t count = sizeof scores / sizeof scores[0];
    int sum = 0;
    for (size_t i = 0; i < count; ++i) {
        sum += scores[i];
    }
    printf("sum=%d, average=%.1f\n", sum, (double)sum / count);
    char name[] = "CS";
    printf("%s, bytes=%zu\n", name, sizeof name);
    return 0;
}

sum은 0→70→150→240이며 평균은 80.0이다. char name[] = "CS";는 'C','S','\0' 세 원소를 갖는다. 문자열 끝을 나타내는 널 문자가 있으므로 sizeof name은 3이다. 'A'는 문자 상수이고 "A"는 널 문자까지 있는 문자열 리터럴이다. %s는 널 문자를 만날 때까지 읽으므로 반드시 유효한 종료와 접근 범위가 필요하다.

sizeof로 원소 수를 구하는 식은 여기처럼 실제 배열 객체가 보이는 자리에서만 쓴다. 함수 매개변수의 int a[]는 포인터 매개변수로 조정되므로 이 방법으로 원래 배열 길이를 복구할 수 없다. 길이를 별도 인자로 전달하는 이유를 다음 장에서 배운다.

2차원 배열 int matrix[2][3]은 ‘int 세 개짜리 배열 두 개’다. 각 행이 순서대로 연속 배치된다. 배열의 크기가 고정되어 있다는 것과 데이터가 연속 배치된다는 것은 별개 성질이다. 필요 크기가 변할 때에는 동적 할당과 용량 관리가 필요하다.

문제 풀기

int a[4]={1,2};와 char s[]="A"의 나머지 원소와 길이는?

a는 {1,2,0,0}으로 나머지가 0 초기화된다. s는 {'A','\0'} 두 원소다. 배열 일부 초기화와 아무 초기화 없는 자동 배열은 다르다.

면접 준비

배열은 같은 형식의 원소를 연속 저장해 인덱스로 접근합니다. 길이 n의 유효 인덱스는 0부터 n−1이며 C는 자동 범위 검사를 보장하지 않습니다. 문자열은 char 배열 안의 널 종료 약속을 함께 지켜야 합니다.
문자열 리터럴을 수정해도 되나?

안 된다. 문자열 리터럴을 수정하려 하면 정의되지 않은 동작이다. 수정하려면 char s[]="CS"처럼 쓰기 가능한 배열에 복사한 형태를 사용한다. 포인터로 받는 읽기 전용 문자열은 const char *로 의도를 드러낸다.

10. 포인터 — 주소와 그곳의 값을 나누기

&x, p, *p를 구분하고 포인터 인자를 이용한 원본 수정과 배열 순회를 설명한다.

주소는 객체의 위치를 가리키는 값이고 포인터는 특정 형식의 객체 등을 가리킬 수 있는 값이다. int *p는 int를 가리키는 포인터 p를 선언한다. 식에서 &x는 x의 주소, *p는 p가 가리키는 객체를 뜻한다. 같은 기호라도 선언과 식에서의 역할을 구분한다.

#include <stdio.h>
void swap(int *left, int *right) {
    int temp = *left;
    *left = *right;
    *right = temp;
}
int main(void) {
    int x = 3;
    int *p = &x;
    *p = 8;
    int y = 10;
    swap(&x, &y);
    printf("%d %d\n", x, y);
    printf("%p\n", (void *)p);
    return 0;
}

먼저 p가 x를 가리키므로 *p=8이 x를 8로 바꾼다. swap은 x와 y의 주소 값을 복사받는다. temp=8→x=10→y=8 순서로 변해 최종 출력은 10 8이다. p 자체를 다른 주소로 바꾸는 것과 *p를 수정하는 것은 다른 작업이다. 주소 출력 %p에는 void *를 전달하며 실제 주소 숫자는 실행마다 달라질 수 있다.

배열 a는 많은 식에서 첫 원소를 가리키는 포인터로 변환된다. a[i]는 *(a+i)와 대응한다. int 포인터 p+1은 주소 숫자를 단순히 1바이트 늘린다는 뜻이 아니라 다음 int 원소를 가리킨다. 배열 객체와 포인터 변수는 동일한 것이 아니다. sizeof 배열과 sizeof 포인터가 다른 이유도 여기 있다.

int sum_array(const int *a, size_t n) {
    int sum = 0;
    for (size_t i = 0; i < n; ++i) {
        sum += a[i];
    }
    return sum;
}

이 함수 조각은 stddef.h 등에서 size_t 선언을 가져와야 한다. a는 읽을 수 있는 int n개를 가리켜야 하며 합은 int 범위 안이라고 가정한다. const int *는 이 포인터를 통해 원소를 수정하지 않겠다는 뜻이다. 길이는 포인터에 자동으로 붙어 오지 않는다.

세 가지 금지

초기화되지 않은 포인터를 역참조하지 않는다. NULL을 역참조하지 않는다. 이미 수명이 끝난 지역변수나 해제한 메모리의 주소를 사용하지 않는다. 배열 끝 바로 다음 포인터는 비교용으로 만들 수 있지만 역참조하면 안 된다. 포인터 산술은 같은 배열의 유효 범위 규칙 안에서 수행한다.

문제 풀기

int a=1,b=2; int *p=&a; p=&b; *p=9; 뒤 a,b는?

a는 1, b는 9다. p를 옮긴 뒤 *p를 썼으므로 바뀐 대상은 b다. 포인터가 처음 가리키던 a가 계속 따라 바뀌는 것은 아니다.

면접 준비

C에서는 포인터도 값으로 전달됩니다. 주소의 복사본으로 같은 객체를 가리키기 때문에 *p를 통해 호출자의 객체를 바꿀 수 있습니다. 포인터 값 변경과 대상 객체 변경을 구분하고 유효 수명과 범위를 확인합니다.
함수 안의 int x 주소를 return하면 왜 위험한가?

일반 자동 지역변수 x는 블록을 떠나면 수명이 끝난다. 반환된 주소로 나중에 그 값을 읽는 것은 유효한 객체 접근이 아니다. 호출자가 마련한 공간이나 수명이 충분한 저장소를 사용해야 한다.

11. 구조체 — 다른 종류의 데이터를 하나로

배열과 구조체의 역할을 구분하고 . 과 ->로 멤버에 접근한다.

배열은 같은 자료형 여러 개를 담고, 구조체는 서로 다른 역할의 멤버를 하나의 타입으로 묶는다. 학생 한 명의 학번과 성적처럼 함께 다루어야 하는 데이터를 표현한다. C 구조체는 C++ 클래스의 상속이나 virtual을 자동 제공하지 않는다.

#include <stdio.h>
struct Student {
    int id;
    double score;
};
void add_bonus(struct Student *student) {
    student->score += 5.0;
}
int main(void) {
    struct Student one = {101, 80.0};
    struct Student copy = one;
    add_bonus(&one);
    printf("%d %.1f %.1f\n", one.id, one.score, copy.score);
    return 0;
}

출력은 101 85.0 80.0이다. one.score는 객체 멤버 접근이고 student->score는 (*student).score와 같다. copy는 구조체 값의 복사본이라 one의 score만 바뀐다. 단, 멤버가 포인터이면 포인터 값이 복사되는 것이지 그 대상까지 자동 복제되지는 않는다.

struct Student group[3];는 학생 세 명의 배열이다. typedef struct Student Student;는 새 데이터 배치를 만드는 것이 아니라 기존 타입에 별칭을 붙인다. 구조체의 크기는 멤버 크기 합과 항상 같지 않다. 정렬 요구를 맞추는 패딩이 들어갈 수 있다.

struct Node {
    int value;
    struct Node *next;
};

이 노드는 값과 다음 노드의 주소를 묶는다. 자기 타입 객체 자체를 멤버로 포함하면 끝없이 크기가 필요하므로 안 되지만, 자기 타입을 가리키는 포인터는 가능하다. 여기까지 배워야 연결 리스트의 data와 next가 선언 가능한 실제 객체로 보인다.

문제 풀기

학생 배열과 학생 구조체는 어떻게 함께 사용할까?

구조체는 학생 한 명의 id·score를 묶고, 그 구조체의 배열은 여러 학생을 같은 형식으로 저장한다. group[1].score처럼 인덱스와 멤버 접근을 조합한다.

면접 준비

구조체는 관련된 여러 멤버를 묶어 하나의 타입으로 만듭니다. 객체에는 점, 포인터에는 화살표로 접근합니다. 값 복사와 포인터 대상의 복사는 구분하고, 구조체 크기에는 패딩이 있을 수 있습니다.
포인터 멤버가 있는 구조체를 대입하면 깊은 복사가 될까?

아니다. 포인터가 담고 있던 주소 값이 복사된다. 두 구조체가 같은 대상에 접근할 수 있으므로 소유권과 해제 책임을 따로 설계해야 한다.

12. 동적 메모리와 C 기초 통합

지역변수와 동적 할당의 수명을 구분하고, 할당→검사→사용→해제를 끝까지 작성한다.

컴파일 시점에 정한 고정 배열 대신 실행 중 필요한 크기의 저장공간을 확보할 때 malloc을 쓴다. stdlib.h의 malloc은 요청한 바이트 수의 저장공간을 확보하고 주소를 반환하거나 실패하면 NULL을 반환한다. 이 공간은 초기화되어 있지 않다. calloc은 할당 공간의 모든 비트를 0으로 만들지만 모든 타입의 의미상 0 표현을 일반적으로 보장한다는 식으로 확장하지 않는다.

#include <stdio.h>
#include <stdlib.h>
int main(void) {
    size_t n = 3;                         // 이 예는 크기를 3으로 제한
    int *scores = malloc(n * sizeof *scores);
    if (scores == NULL) {
        return 1;
    }
    int sum = 0;
    for (size_t i = 0; i < n; ++i) {
        scores[i] = (int)(i + 1) * 10;
        sum += scores[i];
    }
    printf("%d\n", sum);                 // 60
    free(scores);
    scores = NULL;
    return 0;
}

C에서는 malloc의 void * 반환값을 객체 포인터로 변환하기 위해 별도 캐스트를 쓸 필요가 없다. scores라는 포인터 변수의 수명과 malloc으로 확보한 공간의 수명은 다르다. 자동 포인터 변수가 사라져도 할당 공간이 자동으로 free되지는 않는다. 주소를 잃으면 회수할 방법을 잃는 누수가 된다. 반대로 free 후 남은 주소로 읽으면 use-after-free가 된다.

scores=NULL은 그 포인터만 비울 뿐 다른 별칭 포인터까지 무효 접근을 막아 주지 않는다. 같은 할당 공간은 한 번만 해제하고, malloc 계열이 준 시작 주소가 아닌 중간 주소나 지역변수 주소를 free하지 않는다. 실제 외부 입력 n을 사용할 때는 0 처리, 상한, n * sizeof *scores의 크기 계산 오버플로까지 검사해야 한다. 위 예제의 고정 n=3을 무제한 입력 코드라고 생각하지 않는다.

realloc은 크기를 바꾸며 주소가 바뀔 수 있다. 양수 크기 요청이 실패하면 원래 공간은 유지되므로 임시 포인터에 결과를 받아 성공했을 때만 원래 포인터를 바꾸는 방식이 안전하다. 첫 단계에서는 malloc/free를 확실히 익힌 뒤 확장한다.

통합 과제: 학생 세 명의 평균

Student 구조체 배열 세 칸을 마련하고, 각 학생의 id와 score를 대입하고, 반복문으로 합을 구하고, 평균을 반환하는 함수를 작성한다. 포인터와 길이를 인자로 받게 하고 전역변수는 쓰지 않는다. 동적 배열을 쓴다면 실패 검사와 free까지 작성한다. ‘선언·초기화·반복·함수·주소·멤버’의 역할을 줄마다 말할 수 있어야 다음 자료구조로 간다.

C 규칙 확인: WG14 N1570의 6.2(범위·수명·형식), 6.5(표현식), 6.7(선언), 6.8(문장), 7.22.3(메모리 관리). N1570은 C11 공개 초안이며, C17 기초 학습과 공통인 규칙 확인에 사용했다. 컴파일 옵션은 GCC 공식 문서를 참고한다.

문제 풀기

free한 포인터가 NULL이 아니면 아직 사용할 수 있다는 뜻인가?

아니다. free는 포인터 변수의 비트 값을 자동으로 지우지 않는다. 값이 남아 있어도 대상 공간을 사용할 권리는 끝났다. 이후 접근하면 안 된다.

면접 준비

동적 할당은 실행 중 필요한 공간을 마련하는 방법입니다. C에서는 소유권과 해제 책임을 직접 정해야 하며, 포인터 변수의 수명과 할당 객체의 수명은 다릅니다. 실패·범위·해제 후 접근을 모두 확인합니다.
메모리 힙과 자료구조 힙은 같은 것인가?

이름만 같다. 메모리 힙은 흔히 동적 할당에 쓰는 공간을 가리키고, 자료구조 힙은 부모·자식의 우선순위 조건을 유지하는 트리 기반 구조다.

13. 복잡도와 로그를 외우지 않고 이해하기

O(1), O(log n), O(n), O(n log n), O(n²)를 연산 구조에서 설명한다. n은 입력 데이터의 개수라고 정한다.

초 단위 대신 ‘입력이 커지면 얼마나 더 일하는가’

같은 코드도 컴퓨터에 따라 실행 시간이 달라진다. 그래서 크기 n의 입력을 처리할 때 비교나 이동 같은 기본 연산을 몇 번 하는지 본다. 배열의 모든 값을 한 번 읽으면 n번 수준이고, 모든 두 값의 조합을 비교하면 n²번 수준이다. 실제 성능에는 캐시·상수 비용도 영향을 주지만 증가율은 규모가 커질 때의 차이를 보여준다.

비용 모양n=8n=1,024의미
111크기와 무관한 일정 작업
log₂n310절반씩 줄이는 횟수
n81,024전체 한 번

표는 함수값 비교이며 특정 프로그램의 실제 비교 횟수나 실행 시간이 아니다.

로그는 ‘몇 번 곱하면 그 수인가’

2³=8이므로 log₂8=3이다. 역으로 8을 2로 세 번 나누면 1이 된다. 1,024개 후보가 512→256→…→1로 줄면 열 번의 반감이다. 이진 탐색의 비교 횟수는 이와 비슷하게 증가한다. 후보가 1개 남은 뒤의 확인 등으로 정확한 횟수는 달라질 수 있다.

반복문 두 개가 있다고 항상 제곱은 아니다

// work()를 상수 비용의 작업이라고 가정한 함수 내부 조각
for (int i = 0; i < n; ++i) { work(); }
for (int j = 0; j < n; ++j) { work(); } // 2n -> O(n)

for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) { work(); }
} // n*n -> O(n^2)

여기서 work() 한 번은 일정한 비용이라고 가정한다. 안쪽 반복이 매번 n번이 아니라 10번이라면 10n이므로 O(n)이다. 코드의 줄 수보다 실제로 각 작업을 몇 번 실행하는지가 중요하다.

Big O는 충분히 큰 입력에서 비용의 증가를 위에서 제한하는 점근적 상한이다. O 자체가 최악이라는 뜻은 아니다. 최악 비용, 평균 비용 등 분석할 대상을 먼저 정한다. 3n²+5n+7은 O(n²)이다. 이 식은 O(n³)이기도 하지만, 비교할 때는 보통 의미 있는 타이트한 차수를 찾는다. Θ(n²)는 위와 아래를 같은 차수로 제한한다는 뜻이다.

공간복잡도는 필요한 메모리의 증가다. 새 배열 n개를 만들면 추가 공간 O(n), 숫자 변수 몇 개만 쓰면 O(1)이다. 재귀 호출도 저장공간을 쓴다. 입력 저장공간을 포함하는지, 추가 공간만 말하는지 구분한다.

문제 풀기

바깥 n번, 안쪽 5번 반복이면? 바깥 n번마다 후보를 절반씩 줄이면?

첫 번째는 5n번 수준이라 O(n). 두 번째는 매 바깥 회차에 n에서 시작해 1까지 절반씩 줄인다고 가정하면 O(n log n)이다. 안쪽 반복의 시작값과 종료 조건을 확인해야 한다.

면접 준비

시간복잡도는 입력 크기에 따라 연산량이 어떻게 증가하는지 나타냅니다. 이진 탐색은 매번 후보를 절반으로 줄여 O(log n)이고, 전체를 한 번 훑으면 O(n)입니다. Big O는 점근적 상한이므로 평균인지 최악인지 조건을 함께 밝히겠습니다.
O(n)이면 O(n²)보다 항상 빠른가요?

아니다. 작은 입력에서는 상수 비용이나 캐시 동작 때문에 역전될 수 있다. 복잡도는 충분히 큰 입력에서의 증가율 비교이며, 모든 입력 크기에서 실제 실행 시간을 보장하는 순위가 아니다.

동적 배열 추가는 O(1)인데 가끔 전체 복사를 한다면 모순 아닌가요?

한 번의 최악 비용과 여러 번의 총비용을 나눈 상각 비용을 구분한다. 용량을 두 배씩 늘리는 배열에서 복사량은 1+2+4+…처럼 증가해 n번 추가 전체로는 O(n)이다. 따라서 추가 1회의 상각 비용은 O(1), 확장하는 단일 회차의 최악은 O(n)이다. 상각은 입력을 확률적으로 평균내는 평균 분석과 다르다.

순서대로 학습 · 원본 연결

14. 배열·연결 리스트·스택·큐

‘무엇을 자주 할 것인가’에 따라 저장 방식을 고르고, 위치 찾기와 연결 변경 비용을 분리한다.

배열은 나란히, 연결 리스트는 다음 위치를 따라

배열은 같은 크기의 원소를 연속된 위치에 둔다. 시작 주소가 100, 한 원소가 4바이트라면 0번 원소는 100, 1번은 104, 2번은 108에 있다. 주소=시작+인덱스×크기이므로 중간 원소도 앞에서부터 찾아갈 필요가 없다. 이것이 인덱스 접근 O(1)의 이유다.

배열:       [10][20][30]     위치는 연속
연결 리스트: [10|next] → [20|next] → [30|null]
             실제 메모리 위치는 서로 떨어져도 됨

노드(node)는 값과 연결 정보를 묶은 단위다. next는 다음 노드의 주소, null은 다음 노드가 없다는 표시다. 두 번째 이후로 가려면 연결을 따라가므로 k번째 접근은 O(k)다. 이중 연결 리스트는 이전 노드를 가리키는 prev도 둔다.

20 뒤에 25를 넣어 보자

배열 [10,20,30]에서 충분한 용량이 있다고 하자. 30을 한 칸 뒤로 옮기고 빈칸에 25를 넣는다. 뒤에 원소가 많으면 이동도 많다. 리스트에서는 20의 노드를 이미 알 때 ①새 노드 25의 next를 30으로 ②20의 next를 25로 바꾸면 된다. 단, 20을 찾는 과정은 별도다.

배열은 이웃 데이터를 함께 읽기 쉬워 캐시에 유리한 경우가 많다. 리스트는 포인터 저장공간과 메모리 할당 비용이 든다. ‘리스트는 삽입이 빠르므로 항상 낫다’는 결론은 성립하지 않는다.

스택과 큐는 ‘꺼내는 규칙’이다

스택은 LIFO(Last In, First Out), 마지막에 넣은 것이 먼저 나온다. push는 넣기, pop은 맨 위 원소를 제거·반환하기다. 10→20→30을 넣고 pop하면 30이다. 되돌리기와 함수 호출 관리에 연결된다.

큐는 FIFO(First In, First Out), 먼저 넣은 것이 먼저 나온다. enqueue는 뒤에 넣기, dequeue는 앞에서 빼기다. 같은 입력에서 dequeue하면 10이다. 대기열과 BFS에 사용한다. 스택·큐는 제공할 연산의 약속인 추상 자료형(ADT)이고 배열이나 리스트로 구현할 수 있다.

배열 큐에서 앞을 뺄 때마다 전부 왼쪽으로 밀면 O(n)이다. 원형 큐는 front/rear 위치만 다음 칸으로 이동하고 끝에서는 처음으로 돌아가 O(1)로 처리한다. 꽉 참과 비어 있음을 구분하는 크기 변수 등도 필요하다. 리스트 큐는 head와 tail을 함께 유지하면 양 끝 연산을 O(1)로 만들 수 있다.

C로 연결 리스트의 실제 연결 보기

앞에서 배운 구조체와 포인터를 합친다. 아래는 동적 할당 대신 수명이 main 끝까지 유지되는 노드 세 개로 연결 변경만 보여 준다. 주소가 연속인지와 논리적 연결 순서는 별개다.

#include <stdio.h>
struct Node { int value; struct Node *next; };
int main(void) {
    struct Node tail = {30, NULL};
    struct Node head = {10, &tail};
    struct Node middle = {20, head.next};
    head.next = &middle; // 10 -> 20 -> 30
    for (const struct Node *p = &head; p != NULL; p = p->next) {
        printf("%d ", p->value);
    }
    head.next = middle.next; // 20을 논리적으로 연결에서 제외
    return 0;
}

middle.next를 먼저 기존 뒤 노드로 설정하고 head.next를 middle로 바꾼다. 반대로 순서를 잘못 쓰면 기존 연결을 잃을 수 있다. 삭제는 연결에서 제외하는 작업과 동적 할당 공간을 해제하는 작업을 구분한다. 이 예는 자동 객체이므로 free하면 안 된다.

C 배열 스택과 원형 큐 · 경계 검사까지

스택의 size는 현재 원소 수이며 다음 삽입 위치다. push 전에는 용량을, pop 전에는 빈 상태를 검사한다. 아래 함수 조각은 성공하면 1, 실패하면 0을 반환한다. out은 유효한 int 객체를 가리켜야 한다.

enum { CAPACITY = 4 };
struct Stack { int data[CAPACITY]; int size; };
int push(struct Stack *s, int value) {
    if (s->size == CAPACITY) { return 0; }
    s->data[s->size] = value;
    ++s->size;
    return 1;
}
int pop(struct Stack *s, int *out) {
    if (s->size == 0) { return 0; }
    --s->size;
    *out = s->data[s->size];
    return 1;
}
struct Queue { int data[CAPACITY]; int front; int size; };
int enqueue(struct Queue *q, int value) {
    if (q->size == CAPACITY) { return 0; }
    int rear = (q->front + q->size) % CAPACITY;
    q->data[rear] = value;
    ++q->size;
    return 1;
}
int dequeue(struct Queue *q, int *out) {
    if (q->size == 0) { return 0; }
    *out = q->data[q->front];
    q->front = (q->front + 1) % CAPACITY;
    --q->size;
    return 1;
}

사용 전 struct Stack s = {0}; struct Queue q = {0};처럼 초기화한다. 큐의 다음 삽입 위치는 (front+size)%용량이다. size로 빈 상태와 가득 찬 상태를 구분하므로 네 칸 모두 사용할 수 있다. 10,20 삽입 후 제거하면 스택은 20, 큐는 10을 반환한다. 이번 구현의 삽입·제거는 O(1)이고, 일반 연결 리스트에서 같은 연산 이름을 쓴다고 비용이 자동으로 같아지는 것은 아니다.

문제 풀기

빈 스택과 큐에 A,B,C를 넣고 하나 빼고 D를 넣었다. 다음에 무엇이 나오는가?

스택: C를 뺀 후 A,B에 D가 쌓이므로 다음은 D. 큐: A를 뺀 후 B,C 뒤에 D가 붙으므로 다음은 B. ‘마지막 입력’만 보지 말고 남은 상태를 적는다.

네 칸 큐에서 front=3,size=2면 다음 삽입 위치는? 이미 size=4라면?

(3+2)%4=1이다. size=4이면 가득 찼으므로 인덱스를 계산해 덮어쓰기 전에 실패를 반환한다. ‘순환’은 경계를 무시해도 된다는 뜻이 아니다.

면접 준비

배열은 연속 저장으로 인덱스 접근이 O(1)이지만 중간 삽입·삭제에는 이동이 필요합니다. 연결 리스트는 링크를 따라 접근하고, 필요한 노드 위치를 이미 알면 연결 변경이 O(1)입니다. 따라서 탐색 빈도와 수정 위치, 캐시와 메모리 비용까지 보고 선택하겠습니다.
연결 리스트에서 특정 값을 찾아 삭제하면 O(1)인가요?

아니다. 머리에서 값을 찾아가면 최악 O(n)이다. O(1)은 삭제에 필요한 노드와 연결 정보를 이미 알고 있을 때의 변경 비용이다. 단일 리스트의 마지막 노드 삭제 등에서는 이전 노드가 필요하다.

15. 재귀·이진 탐색·분할정복

재귀를 ‘자기 자신을 부른다’에서 끝내지 않고, 작은 문제가 끝난 뒤 어떻게 돌아오는지 설명한다.

작은 답을 받아 큰 답을 만든다

// 입력은 0 <= n <= 100으로 제한한다.
int sum_to(int n) {
    if (n == 0) { return 0; }
    return n + sum_to(n - 1);
}

sum_to(3)은 3에 sum_to(2)의 결과를 더해야 하므로 기다린다. sum_to(2)는 sum_to(1)을 기다리고, sum_to(1)은 sum_to(0)을 기다린다. 마지막 호출이 0을 반환하면 차례로 1, 3, 6이 완성된다.

호출 3→2→1→0종료 조건에서 0 반환반환값 0→1→3→6

기다리는 호출의 지역 상태·복귀 위치를 보관하는 구조가 호출 스택이다. 이 예의 시간은 O(n), 호출 스택 추가 공간도 O(n)이다. 반복문으로 합을 누적하면 추가 공간 O(1)이 가능하다. 종료 조건뿐 아니라 입력이 그 조건에 가까워지는지도 확인한다.

이진 탐색: 왜 절반을 버려도 되는가

오름차순 배열 [2,5,8,11,14,17,20]에서 17을 찾는다. 가운데 11보다 17이 크다. 배열이 정렬되어 있으므로 11의 왼쪽에는 17이 있을 수 없다. 오른쪽 구간만 남기면 가운데가 17이다. 정렬 조건이 후보를 안전하게 버리는 근거다.

// a는 길이 n의 오름차순 int 배열. 0 <= n <= INT_MAX.
int binary_search(const int a[], int n, int target) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (a[mid] == target) { return mid; }
        if (a[mid] < target) { left = mid + 1; }
        else { right = mid - 1; }
    }
    return -1;
}

반복형 이진 탐색은 배열에서 최악 O(log n), 추가 공간 O(1)이다. 탐색이 끝났는데 못 찾으면 −1을 돌려주도록 약속했다. 중복값이 있으면 이 코드는 그중 하나를 찾으며 첫 위치를 보장하지 않는다.

직접 넘겨 보기: 위 배열에서 6 찾기

인쇄·스크립트 미사용 시 추적 요약: (0,6)→mid=3/11 → (0,2)→mid=1/5 → (2,2)→mid=2/8 → (2,1), 탐색 실패.

재귀와 분할정복은 같은 말이 아니다

재귀는 함수 호출 방식이고, 분할정복은 문제를 작은 부분으로 나누어 해결하고 결합하는 설계 전략이다. 병합 정렬은 양쪽을 정렬한 뒤 합친다. 단순히 자기 자신을 호출한다는 이유만으로 모든 재귀가 분할정복이라고 하지는 않는다.

문제 풀기

위 sum_to(4)의 반환값과 동시에 쌓이는 호출 수는?

반환값은 10. sum_to(4), (3), (2), (1), (0)까지 최대 5개의 호출이 쌓인다. 일반 n에서는 n+1개이므로 추가 공간 O(n)이다. 합을 구하는 반복문과 비교해 설명한다.

면접 준비

재귀는 작은 입력에 대한 같은 함수의 결과를 이용하는 방식입니다. 종료 조건과 문제 크기 감소가 필요하고 호출 스택 비용도 봐야 합니다. 이진 탐색은 정렬된 배열의 가운데를 비교해 절반을 제외하므로 최악 O(log n)입니다.
정렬되지 않은 배열에 이진 탐색을 적용하면 왜 안 되나요?

가운데 값보다 작다는 이유로 다른 절반에 답이 없다고 결론낼 수 없기 때문이다. 한 번만 찾는다면 O(n) 순차 탐색이 정렬 후 탐색보다 저렴할 수 있다. 반복 검색이 많을 때는 정렬 비용을 여러 검색에 나누어 생각한다.

순서대로 학습 · 원본 연결

16. 트리·BST·힙·균형 트리

트리의 모양, 검색 규칙, 우선순위 규칙을 구분한다. 같은 ‘이진’ 구조라고 같은 자료구조가 아니다.

계층을 그림으로 표현한다

트리는 연결되어 있고 사이클이 없는 무방향 그래프로 정의할 수 있다. 계층을 설명할 때 기준 노드인 루트(root)를 정한다. 바로 위 노드는 부모, 아래는 자식, 자식이 없는 노드는 잎(leaf)이다. 노드가 n개인 트리의 간선은 n−1개다. 여기서는 깊이와 높이를 간선 수로 센다. 루트 깊이는 0이다.

        8             루트, 깊이 0
      /   \
     3     10         깊이 1
    / \      \
   1   6      14      깊이 2, 이 트리의 높이 2

이진트리는 각 노드의 자식이 최대 두 개이며 왼쪽과 오른쪽이 구분된다. full은 각 노드의 자식이 0개 또는 2개, complete는 마지막 층 전까지 꽉 차고 마지막 층은 왼쪽부터 채움, perfect는 모든 층이 꽉 찬 트리다. 한국어 번역이 혼용되기도 하므로 영어와 정의를 같이 말한다. 위 그림은 일반 이진트리이며 complete도 full도 아니다.

BST: 한 번 비교하면 갈 방향을 알 수 있다

중복 키가 없다고 할 때 이진 검색 트리(BST)의 규칙은 ‘왼쪽 서브트리 전체의 키 < 현재 키 < 오른쪽 서브트리 전체의 키’다. 위 그림에서 6을 찾으면 8보다 작아 왼쪽, 3보다 커 오른쪽으로 간다. 7을 삽입하면 6의 오른쪽 빈자리에 붙는다.

삭제는 잎이면 제거, 자식이 하나면 자식을 위에 연결, 자식이 둘이면 오른쪽 서브트리 최솟값 등으로 대체한 뒤 그 대체 노드를 제거한다. 예를 들어 3을 삭제할 때 6으로 대체하면 1<6<8이라는 순서가 유지된다.

검색·삽입·삭제는 내려가는 길의 길이인 높이 h에 비례해 O(h)다. 1,2,3,4를 순서대로 넣으면 한쪽으로 길어져 높이 n−1이 될 수 있다. 따라서 일반 BST는 최악 O(n)이다. 균형을 유지하면 높이가 O(log n)이 된다.

순회: 언제 현재 노드를 읽느냐

전위는 현재→왼쪽→오른쪽, 중위는 왼쪽→현재→오른쪽, 후위는 왼쪽→오른쪽→현재다. 위 그림의 중위는 1,3,6,8,10,14다. BST의 중위 순회라서 오름차순이지 모든 이진트리의 중위가 정렬 결과인 것은 아니다. 레벨 순회는 큐로 같은 깊이부터 읽는다.

힙: 가장 급한 일 하나를 빨리 고른다

최소 힙은 complete 형태와 ‘부모≤자식’ 조건을 유지한다. 최대 힙은 부등호가 반대다. 형제끼리의 순서는 정하지 않는다. 최소 힙은 최솟값 조회 O(1), 삽입·최솟값 제거 O(log n)이다. 이진 힙에서 임의의 특정 값을 찾는 일은 보통 O(n)이다. 우선순위 큐를 구현할 때 적합하다.

최소 힙 [2,5,3]에 1을 넣으면 마지막에 붙여 [2,5,3,1]. 부모 5와 바꾸어 [2,1,3,5], 다시 부모 2와 바꾸어 [1,2,3,5]. 새 원소가 부모와 비교하며 올라가는 횟수는 높이 이하다. 0부터 시작하는 배열에서 i의 자식 위치는 2i+1, 2i+2다.

AVL·Red-Black·B-tree는 왜 등장하는가

AVL은 각 노드의 왼쪽·오른쪽 높이 차이가 1 이하가 되도록 회전 등으로 조정한다. 3→2→1을 넣어 왼쪽으로 기울면 2를 위로 올려 왼쪽 1, 오른쪽 3으로 만들 수 있다. 회전은 키의 중위 순서를 보존하면서 모양을 바꾼다. Red-Black Tree는 색 규칙을 통해 높이가 O(log n)이 되도록 한다. 둘 다 균형 BST이지만 유지 규칙이 다르다.

B-tree는 노드 하나에 여러 키와 자식을 둔다. 저장장치에서 한 블록씩 읽을 때 많은 분기를 한 번에 확인해 트리 높이와 블록 접근을 줄이려는 목적이다. B+tree는 보통 실제 데이터 항목/레코드 참조를 잎에 두고 잎을 연결해 범위 검색에 유리하게 만든다. 노드의 최대 자식 수를 ‘차수’로 부르는 방식 등 정의 규약이 자료마다 다르니 공식을 외우기 전에 기준을 확인한다.

대조: 기존 트리 기초, 균형 트리 상세·색 규칙. 블록 모델 검토: Open Data Structures §14.2.

문제 풀기

위 BST의 전위·후위·레벨 순회를 적어 보세요.

전위: 8,3,1,6,10,14. 후위: 1,6,3,14,10,8. 레벨: 8,3,10,1,6,14. ‘현재 노드를 언제 읽는가’를 먼저 말하고 왼쪽 부분부터 같은 규칙을 적용한다.

면접 준비

BST는 키의 순서를 이용해 검색하지만 시간은 높이에 비례해 편향되면 O(n)입니다. 균형 검색 트리는 높이를 O(log n)으로 유지합니다. 힙은 전체 검색 순서보다 최솟값 또는 최댓값을 빠르게 꺼내는 데 적합합니다.
힙도 높이가 로그인데 임의 값 검색은 왜 로그가 아닌가요?

부모와 자식의 대소관계만 알 뿐, 목표가 왼쪽/오른쪽 어디에 있는지 BST처럼 한쪽을 배제할 수 없기 때문이다. 최소값이 루트라는 보장과 모든 키를 빨리 찾는 보장은 다르다.

B-tree 대신 이진 균형 트리를 DB 인덱스로 쓰면 안 되나요?

가능 여부보다 접근 비용을 비교한다. 블록 하나에 여러 키를 담고 분기 수를 키우면 같은 수의 키를 더 낮은 높이로 관리해 블록 I/O를 줄일 수 있다. 범위 조회 요구까지 있으면 B+tree의 잎 연결도 도움이 된다. 실제 엔진의 인덱스 구현은 확인해서 말한다.

17. 정렬: 과정에서 복잡도를 도출하기

삽입·병합·퀵 정렬을 손으로 실행하고, 속도뿐 아니라 안정성·추가 메모리·최악 경우를 비교한다.

‘안정적’은 오류가 없다는 뜻이 아니다

정렬은 키라는 기준값으로 순서를 바꾸는 것이다. (민수,80), (지수,80)처럼 키가 같은 두 기록의 원래 순서를 유지하면 안정 정렬이다. 이름순으로 정렬한 결과를 점수순으로 다시 안정 정렬하면 동점자는 이름순이 유지된다.

방법작은 실행 예핵심
선택 정렬[3,1,2]→[1,3,2]→[1,2,3]남은 전체에서 최솟값을 골라 앞자리 확정
삽입 정렬[3|1,2]→[1,3|2]→[1,2,3]정렬된 앞부분에 새 원소를 끼워 넣음
버블 정렬[3,2,1]→[2,3,1]→[2,1,3]이웃 교환으로 이번 최댓값을 뒤로

선택 정렬은 첫 회 n−1번, 다음 n−2번 … 비교하므로 합이 n(n−1)/2다. 입력이 이미 정렬되어도 최솟값을 찾는 표준 구현의 비교는 Θ(n²)다. 삽입 정렬은 이미 정렬되면 새 값을 한 번 확인하고 멈춰 Θ(n)이지만 역순이면 많은 이동이 생겨 Θ(n²)다.

병합 정렬: 먼저 나누고, 두 줄의 맨 앞을 비교한다

[4,1,3,2]
    ↓ 나눔
[4,1]       [3,2]
 ↓   ↓       ↓   ↓
[4] [1]     [3] [2]
    ↓ 합침
[1,4]       [2,3]
    ↓ 두 맨 앞 중 작은 값부터
[1,2,3,4]

[1,4]와 [2,3]을 합칠 때 1 대 2 → 1, 4 대 2 → 2, 4 대 3 → 3, 남은 4를 붙인다. 각 원소를 한 번씩 옮기니 합치는 비용은 O(n)이다. 반씩 나누는 층수가 log₂n이고 각 층 전체 작업이 n 정도여서 Θ(n log n)이 된다.

T(n)=2T(n/2)+Θ(n)의 T(n)은 n개를 정렬하는 비용이다. 2T(n/2)는 절반 크기 정렬 두 번, +Θ(n)은 그 결과를 합치는 비용이다. 수식은 위 그림의 작업량을 적은 것이다. 일반적인 배열 구현은 O(n) 추가 버퍼를 쓰며 같은 키에서 왼쪽을 먼저 고르면 안정적이다.

퀵 정렬: 기준값 양쪽으로 먼저 분리한다

[5,2,4,1,3]에서 기준값(pivot) 3을 정하면 작은 그룹 [2,1], 기준 3, 큰 그룹 [5,4]로 나누고 각 그룹을 정렬한다. 이는 원리 설명용 분할 예이며 실제 제자리 partition의 중간 배열은 구현마다 다르다.

균등 분할이면 각 층 n 정도×로그 층으로 Θ(n log n)이다. 매번 최솟값만 기준으로 골라 0개와 n−1개로 갈리면 n+(n−1)+… 비용이 생겨 Θ(n²)이다. 무작위 pivot은 기대 O(n log n)을 주지만 모든 실행의 최악 시간을 없애지는 않는다. 일반적인 제자리 퀵 정렬은 안정적이지 않고 재귀 스택을 쓴다.

힙 정렬과 비교 정렬 밖의 방법

힙 정렬은 최대 힙의 루트를 맨 뒤로 보내고, 남은 힙을 복구한다. n개를 꺼내며 각 복구가 O(log n)이므로 전체 O(n log n)이다. 아래에서 위로 만드는 초기 힙 생성 자체는 O(n)이며, 대부분의 노드가 잎 가까이에 있어 움직일 거리가 짧기 때문이다.

계수 정렬은 [2,1,2,0]을 값별 개수 [1,1,2]로 세어 재배치한다. n개 입력과 K개 가능한 키 범위를 처리하므로 O(n+K)다. LSD 기수 정렬은 [21,13,12]를 일의 자리로 안정 정렬해 [21,12,13], 십의 자리로 안정 정렬해 [12,13,21]로 만든다. d자리, 기수 b에 대해 보통 O(d(n+b))다. 제한된 키 표현을 활용하므로 비교 정렬의 하한과 모순되지 않는다.

추가 정렬 전체: 기존 비교 정렬, 셸·MSD/LSD·계수 정렬과 조건. 셸 정렬의 복잡도는 간격 수열에 따라 달라지므로 하나의 숫자로 암기하지 않는다.

C 삽입 정렬 — 앞부분이 정렬되어 있다는 약속

// a는 길이 n의 유효한 배열이며 n >= 0이다.
void insertion_sort(int a[], int n) {
    for (int i = 1; i < n; ++i) {
        int key = a[i];
        int j = i;
        while (j > 0 && a[j - 1] > key) {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = key;
    }
}

[3,1,2]에서 i=1이면 key=1을 따로 저장하고 3을 오른쪽으로 옮긴 뒤 1을 넣어 [1,3,2]가 된다. i=2에서 key=2를 저장하고 3을 옮겨 [1,2,3]이 된다. while은 j>0을 먼저 검사해 a[-1] 접근을 막는다. 비교가 >라 같은 키는 앞의 원소를 지나치지 않아 안정적이다. >=로 바꾸면 같은 키의 순서가 바뀔 수 있다.

문제 풀기

[2a,2b,1]에 교환형 선택 정렬을 한 번 적용하면? 안정적인가요?

2a와 최솟값 1을 교환해 [1,2b,2a]가 된다. 같은 키 2의 상대 순서가 뒤집혔으므로 불안정하다. 안정성을 최종 값의 오름차순 여부와 혼동하지 않는다.

면접 준비

병합 정렬은 반씩 나눈 결과를 선형 시간에 합쳐 Θ(n log n)을 보장하고, 배열 구현은 O(n) 추가 공간을 씁니다. 퀵 정렬은 기준값으로 분할하며 평균 O(n log n)이지만 편향 분할이 반복되면 O(n²)입니다. 안정성과 메모리, 최악 보장이 필요한지를 보고 선택하겠습니다.
병합 정렬은 왜 n²가 아니라 n log n인가요?

각 층에는 작은 부분문제가 여러 개 있지만, 그 층의 원소 수를 모두 합치면 n이다. 층의 수는 반감 횟수인 log n이다. n개의 각 원소가 n번씩 움직이는 구조가 아니다.

비교 정렬은 왜 일반적으로 Ω(n log n)의 최악 하한이 있나요?

서로 다른 n개 키의 순서는 n!가지다. 두 키의 비교 결과로 구분하는 결정 트리는 모든 순서를 식별할 만큼 많은 잎을 가져야 하므로 높이가 최소 log₂(n!)이고 이는 Ω(n log n)이다. Ω는 아래쪽 경계다. 계수 정렬은 키를 직접 배열 위치로 쓰므로 이 비교 전용 모델이 아니다.

18. 해시: 빨리 찾기 위해 치르는 비용

해시 함수·충돌·부하율을 작은 테이블로 설명하고, 평균 O(1)의 조건을 말한다.

키를 칸 번호로 바꾼다

학번으로 학생 정보를 찾고 싶다. 모든 학생을 비교하는 대신 해시 함수 h(k)=k mod 7을 사용하자. mod는 나눈 나머지다. 10 mod 7=3이므로 10은 3번 칸을 찾는다. ‘해시 값이 같으면 원본도 같다’는 뜻은 아니다. 17도 나머지 3이므로 충돌한다.

분리 연결법 (chaining)
칸 0: 비어 있음
칸 3: (10,정보A) → (17,정보B) → (24,정보C)

선형 탐사 (linear probing), 위 순서대로 삽입
칸 3: 10   칸 4: 17   칸 5: 24

분리 연결법은 같은 칸에 들어온 항목들을 별도의 리스트 등으로 관리한다. 선형 탐사는 테이블 안에서 다음 칸을 확인하다 빈곳에 둔다. 17을 검색할 때는 계산된 3번에서 시작해 10은 다른 키이므로 4번까지 확인한다. 각 항목의 실제 키 비교가 필요하다.

평균 O(1)에도 관리 조건이 있다

부하율 α=n/m은 항목 수 n을 테이블 칸 수 m으로 나눈 값이다. 7칸에 5개면 5/7이다. 균등하게 분산되는 해시와 적절한 부하율을 가정할 때 빠른 평균 검색을 기대한다. 분리 연결법은 평균 O(1+α), 충돌이 한 칸에 몰리면 기본 리스트 버킷에서 최악 O(n)이다. 선형 탐사 같은 개방 주소법은 빈칸이 줄면 긴 탐사가 생긴다.

테이블을 늘리면 칸 번호 계산도 바뀔 수 있어 항목들을 재배치하는 rehash가 필요하다. 확장 1회는 O(n)일 수 있고, 적절한 확장 정책 아래 삽입의 상각 비용을 따로 분석한다. 긴 문자열 키라면 해시 계산 자체에 키 길이 L에 비례하는 비용도 생긴다. O(1)은 보통 키 처리 비용을 일정하게 보는 모델이다.

해시와 트리 중 무엇을 고를까

‘학번이 정확히 100인 학생’ 같은 일치 조회에는 해시를 고려한다. ‘학번 100부터 200까지’, ‘가장 작은 키부터’ 같은 범위·순서 조회에는 균형 검색 트리가 자연스럽다. 빨리 저장한다는 사실이 정렬 순서를 보장해 주지는 않는다.

원본 대응: 검색·충돌 상세, 해시 함수 5종과 보안.

원본 6쪽: 해시 함수를 만드는 방법

제산법은 정수 키를 테이블 크기 m으로 나눈 나머지를 사용한다. 예를 들어 m=7이면 10과 17은 모두 3번 칸에 대응하여 충돌한다. 폴딩은 키를 여러 조각으로 나누어 더하는 방식, 중간제곱법은 키를 제곱한 값의 중간 자릿수를 사용하는 방식이다. 숫자 분석법은 키 분포를 분석해 변별력 있는 자릿수를 고른다. 문자열은 문자 코드를 차례로 누적하는 다항식 형태로 계산할 수 있다. 어떤 방법도 모든 입력에 충돌이 없다는 보장은 없다.

문제 풀기

위 선형 탐사 테이블에서 10을 그냥 ‘빈칸’으로 지우면 24 검색에 무슨 문제가 생기나요?

검색이 원래 시작 칸 3에서 빈칸을 만나 ‘없다’고 멈추면 실제 5번의 24를 놓친다. 검색은 계속하되 삽입에 활용할 수 있는 삭제 표시(tombstone)를 두거나 적절히 재배치해야 한다.

h(k)=k mod 7에 10,17,24를 넣으면 충돌이 몇 번 발생하고 어떻게 처리할까?

모두 3번 칸으로 대응한다. 첫 키 뒤의 두 삽입에서 이미 점유된 칸과 충돌한다. 체이닝이면 같은 버킷에 연결하고, 선형 탐사라면 비어 있는 다음 칸을 찾는다.

면접 준비

해시 테이블은 키를 칸 번호로 계산해 접근합니다. 서로 다른 키가 같은 칸에 들어가는 충돌은 연결법이나 탐사법으로 처리합니다. 좋은 분산과 적절한 부하율에서 평균 O(1)을 기대하지만, 충돌이 몰리면 최악 O(n)이 될 수 있고 범위 검색에는 트리를 고려합니다.
해시를 비밀번호 저장에도 그대로 사용하면 되나요?

테이블용 해시는 빠른 분산을 위한 것이고 비밀번호 저장은 공격 비용을 높이는 목적이다. 비밀번호에는 salt와 전용 비밀번호 해싱 방식 등이 필요하다. 빠른 테이블 해시를 보안 기능으로 대체하면 안 된다. 보안 목적의 구분은 27장에서 이어진다.

19. 그래프·BFS·DFS·최단경로·MST

탐색 순서와 경로 최적화 목적을 구분하고, 작은 그래프에서 직접 실행한다.

점은 대상, 선은 관계다

그래프의 정점(vertex)은 도시·사람 같은 대상, 간선(edge)은 도로·친구 같은 관계다. 방향이 있으면 A→B와 B→A가 다를 수 있고, 가중치(weight)는 거리·비용 등을 뜻한다. 경로는 간선을 따라 이동하는 순서, 사이클은 돌아오는 순환이다. 복잡도에서는 V를 정점 수, E를 간선 수로 쓰겠다.

무방향 그래프의 이웃 목록
A: B, C
B: A, D
C: A, D
D: B, C, E
E: D

인접 리스트는 이웃만 저장해 O(V+E) 공간이다. 인접 행렬은 V×V 표에서 연결 여부를 저장해 O(V²) 공간이며 두 점의 간선 여부를 O(1)에 확인한다. 간선이 드문 그래프에서는 목록 방식이 메모리에 유리하다.

BFS: 가까운 층부터, 큐로 처리한다

꺼내는 정점새로 발견해 넣는 정점처리 후 큐
시작 전A[A]
AB,C[B,C]
BD[C,D]
C없음, D는 이미 발견[D]
DE[E]
E없음[]

큐에 넣을 때 방문 표시를 해 중복 삽입을 막는다. 발견 시 이전 정점을 기록하면 E←D←B←A를 역으로 따라 A-B-D-E 경로를 얻는다. 모든 간선 비용이 같다면 먼저 발견한 경로의 간선 수가 최소다. 방문 순서가 같지 않아도 올바른 BFS일 수 있으며, 여기서는 이웃을 알파벳순으로 본다.

DFS: 한 방향을 끝까지 확인한 뒤 돌아온다

재귀 DFS로 위 그래프를 알파벳순 탐색하면 A→B→D→C까지 간 뒤 D로 돌아와 E를 방문한다. 방문 순서는 A,B,D,C,E다. 재귀 호출 또는 명시적 스택을 사용한다. 사이클이 있어 방문 표시가 없으면 반복 방문할 수 있다. 인접 리스트에서 DFS/BFS 모두 각 정점·간선을 일정 횟수씩 처리해 O(V+E), 탐색용 방문 배열·스택·큐는 O(V)다. 그래프 저장공간은 별도다.

가중치가 다르면 ‘적은 간선’이 ‘싼 경로’가 아니다

A-B=10, A-C=1, C-B=1이면 B로 직접 가는 한 간선의 비용은 10, C를 거치는 두 간선은 2다. 일반 BFS는 최소 간선 수를 찾으므로 최소 비용을 보장하지 않는다. Dijkstra는 음수 가중치가 없는 그래프에서 현재 알려진 누적 거리가 가장 짧은 정점을 확정하며 거리를 갱신한다.

Dijkstra 추적: 시작 거리 A=0, B=∞, C=∞ → A 처리 후 B=10,C=1 → C 선택 후 B=min(10,1+1)=2 → B 선택. ∞는 아직 경로를 모른다는 표시다. ‘완화(relaxation)’는 새 경로가 더 짧으면 거리 추정값을 바꾸는 것이다. 음수 간선이 있으면 아직 안 본 경로가 이미 확정한 거리를 더 낮출 수 있어 이 확정 논리가 깨진다.

MST: 한 출발점의 거리가 아니라 전체 연결 비용

최소 신장 트리(MST)는 연결된 무방향 가중 그래프의 모든 정점을 사이클 없이 잇는 방법 중 간선 합이 최소인 것이다. 건물마다 전선을 연결하는 총비용을 최소화하는 문제로 생각한다. 연결되지 않았으면 전체의 신장트리가 없고 성분별 최소 신장 숲을 구할 수 있다.

Kruskal은 전체 간선을 싼 순서로 보며 사이클을 만들지 않는 간선을 고른다. Union-Find는 두 정점이 이미 같은 연결 성분인지 확인한다. Prim은 현재 트리와 바깥 정점을 잇는 간선 중 가장 싼 것을 골라 한 트리를 확장한다. Prim이 보는 값은 ‘붙이는 간선 하나’, Dijkstra가 보는 값은 ‘시작점부터 누적 거리’다.

A-B=2, A-C=2, B-C=1에서 Kruskal은 B-C(1), A-B(2)를 고르면 합 3인 MST다. 이 트리에서 A→C 경로는 비용 3이지만 원래 그래프에는 비용 2인 A-C가 있다. 전체 연결 비용 최소와 각 목적지 최단거리는 다른 목표다.

기존 상세·정정: 탐욕 선택, 그래프·MST·Borůvka.

원본 8~9쪽: 탐욕 선택과 Borůvka

탐욕법은 매 단계에서 현재 기준에 가장 좋은 선택을 한다. 항상 전역 최적해를 보장하는 일반 원칙은 아니며, 문제별 안전성 근거가 필요하다. MST에서는 한 연결 성분과 바깥을 잇는 최소 가중치 간선을 고르는 절단 속성이 핵심이다.

Borůvka(솔린) 알고리즘은 처음에 각 정점을 별도 성분으로 두고, 각 성분에서 바깥으로 나가는 가장 싼 간선을 고른 뒤 성분을 병합한다. 선택 간선의 중복과 사이클을 검사하고 동률을 일관되게 처리한다. 연결 그래프에서 성분 수가 단계마다 줄어, 간선을 매 단계 훑는 구현은 O(E log V)이다. 연결되지 않은 그래프에서는 최소 신장 숲을 구한다. Dijkstra는 한 출발점의 최단경로, Prim·Kruskal·Borůvka는 전체 연결 비용 최소화가 목적이다.

문제 풀기

위 그래프에서 A에서 E까지 최소 간선 수는? 경로가 하나뿐인가요?

3개다. A-B-D-E와 A-C-D-E가 모두 가능하다. BFS에서 어느 경로를 기록하는지는 이웃 처리 순서에 따라 달라질 수 있다. 최단경로가 유일하다는 보장은 없다.

면접 준비

BFS는 큐로 가까운 층부터 탐색해 같은 간선 비용에서 최단경로를 찾습니다. DFS는 스택이나 재귀로 깊게 진행합니다. 가중치가 다르면 조건에 맞는 최단경로 알고리즘을 골라야 하며, MST는 개별 경로가 아니라 전체를 잇는 간선 합을 최소화하는 별도 문제입니다.
왜 탐욕적으로 고르면 언제나 최적이라고 할 수 없나요?

현재 최선이 전체 최선을 보존한다는 근거가 필요하다. 동전 1,3,4로 6을 만들 때 큰 동전부터 고르면 4+1+1의 3개지만 최적은 3+3의 2개다. MST에서는 현재 선택을 존중하는 절단을 가로지르는 최소 가중치 간선이 안전하다는 절단 성질이 근거다.

그래프 알고리즘의 시간복잡도는 모두 O(V+E)인가요?

아니다. 인접 리스트 DFS/BFS가 O(V+E)다. Kruskal은 간선 정렬 때문에 보통 O(E log E), 배열·행렬 Prim은 O(V²), 이진 힙·인접 리스트 기반 Dijkstra는 보통 O((V+E) log V)다. 어떤 자료구조로 무엇을 수행하는지 먼저 지정한다.

가장 싼 간선을 고른다는 점에서 Dijkstra와 Prim은 같은가요?

아니다. Dijkstra는 출발점에서 누적된 거리로 다음 정점을 확정한다. Prim은 현재 트리와 바깥 정점을 잇는 간선의 비용으로 선택한다. 같은 그래프에서도 결과와 목적이 다르다.

순서대로 학습 · 원본 연결

20. 프로그램이 실행되면: 프로세스·스레드

운영체제의 역할을 자원 관리와 보호로 설명하고, 프로세스와 스레드의 공유 범위를 구분한다.

파일과 실행 중인 존재는 다르다

디스크의 프로그램 파일은 실행할 명령과 데이터다. 실행하면 운영체제(OS)는 주소 공간과 실행 상태 등을 준비해 프로세스로 관리한다. 같은 프로그램 파일을 두 번 실행하면 별개의 프로세스가 생길 수 있다. 운영체제는 CPU 시간·메모리·장치를 여러 프로그램에 배분하고 서로의 자원을 함부로 침범하지 않도록 보호한다.

커널(kernel)은 운영체제 핵심 부분이다. 일반 프로그램은 파일 읽기 같은 요청을 시스템 호출(system call)로 전달한다. 사용자 모드와 커널 모드는 권한을 구분한다. 시스템 호출로 권한 모드가 바뀌는 것과 다른 프로세스·스레드로 실행 대상이 바뀌는 문맥교환은 같은 사건이 아니다.

프로세스 안에서 여러 실행 흐름을 둔다

스레드는 프로세스 안의 실행 흐름이다. 일반적으로 같은 프로세스의 스레드는 코드·전역 데이터·힙·열린 파일 등의 자원을 공유하고, 각자의 레지스터 상태·프로그램 카운터·스택을 갖는다. 프로그램 카운터는 다음에 실행할 명령 위치를 나타낸다. 스택은 각 호출이 어디로 돌아갈지 등의 정보를 관리한다.

관점프로세스같은 프로세스의 스레드
주소 공간보통 서로 분리공유
데이터 교환파이프·메시지·공유 메모리 등의 IPC공유 메모리로 쉽게 접근, 동기화 필요
오류 영향주소 공간 격리로 완화 가능잘못된 메모리 접근 등이 프로세스 전체에 영향 가능
실행 상태자원과 실행 흐름을 함께 관리스레드별 스택·레지스터 등

프로세스도 명시적으로 공유 메모리를 사용할 수 있다. 스레드별 스택이 따로 있다는 말은 같은 주소 공간의 다른 스레드에서 해당 메모리가 절대 접근 불가능하다는 뜻은 아니다.

동시성·병렬성·문맥교환

동시성(concurrency)은 여러 작업이 겹친 기간에 진행되는 성질이다. 단일 코어에서도 A 일부→B 일부→A 나머지처럼 번갈아 진행할 수 있다. 병렬성(parallelism)은 실제로 같은 시각에 여러 작업을 실행하는 것이다. 여러 코어 등이 있어야 CPU 연산을 병렬로 실행할 수 있다.

문맥교환은 A의 실행 상태를 저장하고 B의 상태를 복원하는 과정이다. 같은 프로세스의 스레드 사이 전환은 주소 공간 전환 부담이 적을 수 있지만 캐시 등 다른 비용도 존재한다. ‘스레드 전환은 항상 빠르다’고 단정하지 않는다.

준비: CPU를 기다림실행: CPU 사용대기: I/O 등 사건 기다림사건 완료 후 준비로

준비 상태와 대기 상태의 차이는 CPU만 받으면 실행할 수 있는지다. 대기 중인 작업에 CPU를 줘도 기다리는 I/O가 끝나지 않으면 진행할 수 없다.

기존 프로세스·스레드, fork. 추가 읽기: OSTEP의 Process·CPU Virtualization 장.

문제 풀기

한 코어에서 A와 B를 번갈아 실행한다면 동시성인가요, 병렬성인가요?

동시성은 있지만 CPU 실행의 병렬성은 아니다. 시간 전체로 보면 둘 다 진척하지만 한 시점의 해당 코어에서는 하나의 명령 흐름을 실행한다는 모델이다.

면접 준비

프로세스는 실행 중인 프로그램으로 자원과 주소 공간의 관리 단위입니다. 스레드는 그 안의 실행 흐름으로 코드·힙 등을 공유하지만 각자의 실행 상태와 스택을 가집니다. 공유로 통신이 쉬운 대신 경쟁 상태를 동기화해야 하고, 동시 실행이 곧 병렬 실행을 뜻하지는 않습니다.
스레드는 모두 공유하니까 스택도 하나만 쓰나요?

각 스레드는 서로 다른 함수 호출 위치에서 실행될 수 있으므로 별도의 호출 스택과 레지스터 상태를 가진다. 같은 주소 공간을 쓴다는 것과 호출 상태를 하나로 합친다는 것은 다르다.

fork()를 호출하면 무엇이 달라지나요?

호출한 프로세스를 바탕으로 자식 프로세스가 생긴다. 성공 시 부모에게 자식 PID, 자식에게 0이 반환되어 코드에서 두 흐름을 구분할 수 있다. 메모리는 논리적으로 독립하며 실제 복사는 copy-on-write로 늦출 수 있다. 이는 같은 프로세스 안에 스레드를 만드는 것과 다르다.

순서대로 학습 · 원본 연결

21. 가상 메모리·페이지 폴트·캐시

가상 주소를 물리 주소로 바꾸는 과정을 계산하고, 캐시 미스·TLB 미스·페이지 폴트를 구분한다.

왜 주소를 한 번 더 변환할까

프로세스마다 ‘내가 사용할 주소 공간’을 제공하면 다른 프로그램의 배치를 몰라도 코드를 실행하고, 접근 권한도 관리하기 쉽다. 이때 프로그램이 사용하는 것이 가상 주소, RAM의 실제 위치가 물리 주소다. MMU라는 하드웨어가 운영체제가 준비한 매핑을 이용해 주소를 변환한다. 가상 메모리를 단순히 ‘RAM이 부족하면 디스크를 쓰는 기능’으로만 정의하면 주소 변환과 보호 목적을 놓친다.

페이징: 같은 크기로 나누고 대응표를 둔다

가상 공간의 고정 크기 조각은 페이지(page), RAM의 같은 크기 조각은 프레임(frame)이다. 페이지 테이블은 어느 페이지가 어느 프레임에 놓였는지, 접근 가능한지 등을 기록한다. 한 프로세스의 페이지들이 RAM에 연속해 있을 필요는 없다.

단위부터 계산해 보자

교육용으로 페이지 크기를 1,024바이트라고 하자. 가상 주소 2,500은 2×1,024+452이므로 페이지 번호 2, 페이지 안 위치(offset) 452다. 페이지 2가 프레임 7에 매핑되면 물리 주소는 7×1,024+452=7,620이다. 페이지 번호만 프레임 번호로 바뀌고 offset은 유지된다.

TLB·캐시는 서로 다른 것을 가까이 둔다

TLB(Translation Lookaside Buffer)는 최근 주소 변환 정보를 저장한다. CPU 캐시는 실제 명령·데이터의 일부를 가까이 저장한다. TLB에 변환이 없으면 페이지 테이블을 조회할 수 있고, 해당 페이지가 RAM에 정상적으로 있으면 페이지 폴트 없이 계속 실행할 수 있다. CPU 캐시 미스도 더 아래 메모리 계층에서 데이터를 가져오는 것이며 곧바로 디스크 접근을 뜻하지 않는다.

가상 주소TLB / 페이지 테이블로 변환권한·매핑 확인캐시 / RAM 접근

개념 이해를 위한 순서다. 실제 하드웨어에서는 일부 조회가 겹치거나 캐시 설계에 따라 순서가 달라질 수 있다.

페이지 폴트는 운영체제의 처리가 필요한 예외

필요한 페이지가 현재 RAM에 없거나 접근 권한·매핑 문제로 바로 사용할 수 없으면 페이지 폴트가 발생할 수 있다. 운영체제는 합법적인 접근인지 확인한다. 디스크에 있는 유효한 페이지라면 프레임을 확보하고 데이터를 적재한 뒤 매핑을 갱신해 명령을 재실행할 수 있다. 잘못된 주소 접근이면 프로그램에 오류를 전달하거나 종료할 수 있다. 처음 쓰는 페이지를 0으로 채우거나 copy-on-write를 처리하는 등 디스크 읽기가 없는 경우도 있다.

페이지 교체를 손으로 해 보기

프레임 3개에서 FIFO는 들어온 지 가장 오래된 페이지를 내보낸다. 참조열 1,2,3,1,4이면 1·2·3에서 폴트 세 번, 다시 1은 적중, 4에서 1을 내보내 폴트 한 번: 총 4회다. FIFO는 최근에 사용했어도 처음 들어온 1을 교체한다.

LRU는 가장 오랫동안 사용하지 않은 것을 내보낸다. 같은 참조열에서는 마지막에 2를 내보낸다. OPT는 미래에 가장 늦게 쓸 것을 내보내는 이론적 기준이다. LFU는 사용 횟수가 적은 것을 고른다. working set은 일정 구간에 활발히 참조하는 페이지 집합이고, 이를 RAM이 수용하지 못해 실행보다 교체에 시간을 많이 쓰면 thrashing(스래싱)이다.

단편화와 지역성

내부 단편화는 할당된 블록 안의 낭비다. 4KiB 페이지로 6KiB를 담으면 8KiB를 차지해 마지막 2KiB가 남는다. 외부 단편화는 빈 공간이 흩어져 필요한 연속 공간을 못 얻는 문제다. 가변 크기 논리 구간을 쓰는 세그멘테이션에서 대표적으로 나타난다.

시간 지역성은 최근 사용한 것을 다시 쓰는 경향, 공간 지역성은 가까운 주소를 이어 쓰는 경향이다. 반복문이 같은 누적값을 갱신하면 시간 지역성, 배열을 차례대로 읽으면 공간 지역성의 예다. 캐시는 이를 이용해 평균 접근 지연을 줄인다.

원본 대응: 메모리·캐시, 가상 메모리, 요구 페이징.

원본 2·10쪽: 교체 정책을 비교하는 기준

OPT는 앞으로 가장 늦게 사용할 페이지를 교체하므로 실제 미래를 모르는 운영체제에서는 비교 기준으로 쓴다. FIFO는 들어온 순서, LRU는 마지막 사용 시각, LFU는 누적 사용 횟수를 기준으로 삼는다. LFU는 오래전에 자주 쓴 페이지가 남는 문제를 완화하려고 시간에 따른 감쇠 등을 고려할 수 있다. FIFO에서는 프레임을 늘렸는데도 페이지 폴트가 증가하는 Belady 현상이 가능하다. 캐시와 가상 메모리는 계층과 관리 단위가 다르므로 같은 정책 이름이 쓰인다고 동일한 장치로 생각하면 안 된다.

문제 풀기

페이지 크기 1,024, 가상 주소 3,500, 해당 페이지가 프레임 9라면 물리 주소는?

3,500=3×1,024+428. 페이지 번호 3, offset 428. 물리 주소는 9×1,024+428=9,644다. 매핑이 유효하고 접근 권한이 있다는 가정이다.

면접 준비

가상 메모리는 프로그램의 주소와 물리 메모리 위치를 분리해 주소 공간과 보호를 제공합니다. 페이징은 페이지를 프레임에 매핑합니다. TLB는 주소 변환 정보, 캐시는 데이터·명령을 저장하며, 페이지 폴트는 매핑이나 접근을 처리해야 하는 예외로 모든 경우가 디스크 읽기는 아닙니다.
페이지 크기를 크게 하면 무조건 좋아지나요?

같은 주소 공간에 필요한 페이지 테이블 항목 수가 줄고 TLB 하나가 덮는 범위는 커질 수 있다. 반면 내부 단편화와 불필요하게 가져오는 데이터가 늘 수 있다. 접근 패턴과 하드웨어 조건에 따른 절충이다.

자료구조 힙과 메모리 힙은 같은 뜻인가요?

아니다. 자료구조 힙은 우선순위 규칙을 가진 트리형 구조, 메모리 힙은 동적 할당 공간을 부르는 이름이다. 메모리 스택은 호출 수명에 맞춰 쓰는 영역이다. C의 동적 할당은 malloc/free, 다른 언어는 언어별 수명 관리 규칙을 따른다.

22. 스케줄링·경쟁 상태·교착상태

실행 순서를 표로 추적해 잘못된 결과가 생기는 이유와 동기화가 해결하는 범위를 설명한다.

CPU를 누구에게 얼마나 줄까

FCFS는 먼저 도착한 작업부터 실행한다. SJF는 다음 CPU 사용 구간이 짧은 작업을 먼저 고르지만 길이를 알아야 하거나 예측해야 한다. 우선순위 방식은 높은 우선순위를 먼저 고르며, 낮은 작업이 계속 밀리는 기아(starvation)가 생길 수 있다. 기다릴수록 우선순위를 높이는 aging으로 완화할 수 있다.

선점은 실행 중인 작업에서 CPU를 회수해 다른 작업으로 바꿀 수 있다는 뜻이다. Round Robin(RR)은 time quantum이라는 시간 조각만큼 번갈아 실행한다. 시간 조각이 작으면 반응 기회는 자주 오지만 문맥교환 부담이 커진다.

A는 5, B는 2만큼 CPU가 필요하고 둘 다 시각 0 도착

문맥교환 비용은 무시하고 A부터 시작한다. FCFS: A(0–5), B(5–7). 대기시간은 A=0, B=5, 평균 2.5. RR, quantum=2: A(0–2), B(2–4 완료), A(4–6), A(6–7 완료). 완료시간은 A=7, B=4, 대기시간은 A=7−5=2, B=4−2=2, 평균 2다. 응답시간은 최초 실행까지이므로 A=0, B=2다.

반환시간은 도착부터 완료까지, 대기시간은 준비 큐에서 기다린 시간, 응답시간은 처음 실행·응답할 때까지다. 위의 반환−CPU시간 계산은 I/O 대기가 없는 예제의 조건에서 쓴다. 목표가 응답성인지 처리량인지에 따라 평가가 달라진다.

한 줄 코드도 여러 단계로 실행될 수 있다

x=0에 두 작업이 각각 x=x+1을 실행한다고 하자. 이를 읽기→더하기→쓰기로 나눈 교육용 모델을 보자.

순서작업 A작업 B공유 x
1x 읽음: 00
2x 읽음: 00
3읽은 값+1을 씀1
4읽은 값+1을 씀1

기대한 2가 아니라 1이 됐다. 실행 순서에 따라 결과가 달라지는 경쟁 상태(race condition)의 예다. 특정 언어의 실제 메모리 모델에서 이 코드를 안전하다고 가정하면 안 되며, 예를 들어 C/C++의 동기화되지 않은 데이터 경쟁은 정의되지 않은 동작이 될 수 있다.

임계구역을 하나의 작업만 수행하게 한다

임계구역은 공유 상태를 다루어 보호가 필요한 코드 구간, 상호배제는 그 구간에 한 번에 하나만 들어가게 하는 성질이다. mutex를 잠그고 읽기·더하기·쓰기를 모두 수행한 뒤 풀면 위 순서의 겹침을 막을 수 있다. 원자적 연산(atomic operation)은 다른 실행에서 중간 상태가 보이지 않는 하나의 연산처럼 처리되도록 제공되는 연산이다.

세마포어(semaphore)는 원자적인 wait/signal로 자원 수나 실행 순서를 제어한다. 자원 3개라면 최대 세 작업이 자원을 획득하도록 모델링할 수 있다. mutex는 보통 잠근 실행 주체가 풀어야 하는 소유권 규칙이 있고, 세마포어와 용도가 완전히 같지 않다. monitor는 공유 데이터와 접근 절차를 묶고 상호배제를 제공한다. 조건 변수는 조건을 기다리고 알리는 데 쓰며, 깨어났다고 조건이 여전히 참이라는 보장은 없어 일반적으로 조건을 반복 확인한다.

잠금이 새 문제를 만들 수도 있다

A는 잠금 L1을 잡고 L2를 기다리고, B는 L2를 잡고 L1을 기다리면 둘 다 진행하지 못한다. 이것이 교착상태(deadlock)다. 대표 필요 조건은 상호배제, 점유 대기, 비선점, 순환 대기다. 모든 작업이 L1→L2처럼 같은 순서로 잠금을 획득하도록 하면 이 예의 순환 대기를 깨뜨릴 수 있다.

예방은 조건 중 하나가 생기지 않도록 설계, 회피는 앞으로도 완료 순서가 가능한 안전 상태를 유지하며 자원 할당, 탐지·복구는 생긴 교착을 찾아 해소하는 접근이다. CPU 스케줄링의 선점과 교착 조건에서 말하는 자원 비선점은 구분한다.

기존 스케줄링·동기화·모니터·분산. 추가 읽기: OSTEP의 Concurrency·Locks·Semaphores 장.

문제 풀기

A=4, B=1, 둘 다 시각 0 도착. A부터 FCFS로 실행하면 평균 대기시간은?

A는 0, B는 4만큼 기다리므로 평균 (0+4)/2=2다. B부터 SJF로 실행하면 B=0,A=1로 평균 0.5다. 실행 길이를 알고 I/O와 전환 비용을 무시한 예다.

면접 준비

공유 변수의 읽기·수정·쓰기가 겹치면 갱신이 사라지는 경쟁 상태가 생길 수 있습니다. 임계구역 전체를 mutex 등으로 보호해 상호배제를 확보합니다. 다만 여러 잠금을 서로 다른 순서로 잡으면 교착상태가 생길 수 있어 일관된 잠금 순서 등을 고려하겠습니다.
교착상태와 기아는 어떻게 다른가요?

교착은 관련 작업들이 서로 자원을 기다려 진행하지 못하는 상태다. 기아는 다른 작업은 진행하지만 특정 작업이 계속 선택되지 않는 상태다. 우선순위 aging은 기아 완화책이지 모든 교착의 해결책이 아니다.

비교적 작은 코드인데 잠금을 빼도 되지 않나요?

코드 길이보다 공유 상태의 접근 방식과 원자성·실행 순서가 중요하다. 안전한 원자 연산이나 공유하지 않는 설계로 대체할 수는 있지만, 짧다는 이유로 동기화를 생략할 근거는 없다.

23. 네트워크: 주소를 입력한 뒤 생기는 일

프로토콜은 서로 이해하기 위한 약속

이 대응은 학습용이며 실제 프로토콜이 OSI의 모든 경계에 정확히 들어맞는 것은 아니다. 캡슐화는 상위 데이터를 담고 각 계층에 필요한 제어 정보를 덧붙이는 과정이다.

이름·IP·MAC·포트는 다른 질문에 답한다

DNS는 도메인 이름에 대한 IP 주소 등 레코드를 조회하는 시스템이다. IP 주소는 네트워크 간 전달에, MAC 주소는 해당 링크의 프레임 전달에 쓰는 인터페이스 주소다. 포트 번호는 전송 계층에서 통신 끝점을 구분하는 데 쓰인다. 하나의 기기에도 여러 서비스가 있으므로 IP만으로 어떤 서비스와 통신할지 충분하지 않다.

IPv4 LAN에서 ARP는 다음 홉의 IPv4 주소에 대응하는 링크 주소를 알아내는 데 사용한다. 외부 서버에 보낸다면 보통 원격 서버 MAC을 찾는 것이 아니라 같은 링크에 있는 기본 게이트웨이의 MAC을 찾는다. IP/MAC 변환과 가상/물리 메모리 주소 변환은 별개다.

간단한 웹 요청을 따라가기

  1. 브라우저가 서버 이름을 해석한다. DNS 캐시가 있으면 조회 일부가 생략될 수 있다.
  2. 목적지 IP로 가기 위한 경로와 다음 홉을 정한다. 같은 LAN의 다음 홉 주소가 필요하면 ARP 등을 사용한다.
  3. HTTPS를 TCP 기반으로 사용하는 예에서는 TCP 연결 후 TLS로 서버 인증과 암호화 통신을 준비한다.
  4. HTTP 요청을 보내고 응답을 받는다. 응답에는 HTML·다른 리소스를 요청할 정보 등이 들어갈 수 있다.
  5. 브라우저가 받은 내용을 해석하고 화면을 구성한다.

기존 연결·캐시·프록시 여부에 따라 생략되거나 달라지는 단계가 있다. 모든 HTTP가 TCP 위에서 동작하지는 않으며 HTTP/3는 QUIC을 사용한다. 처음에는 위 TCP 기반 예를 이해한 뒤 예외를 구분한다.

TCP와 UDP: 무엇을 보장해 주는가

TCP는 연결 지향의 신뢰성 있는 순서 있는 바이트 스트림을 제공한다. 순서 번호·확인 응답·재전송 등을 사용한다. 애플리케이션이 ‘안녕’과 ‘반가워’를 두 번 보냈다고 수신도 정확히 두 번에 나뉘는 것은 아니다. 메시지 경계는 길이 정보 등의 응용 규칙으로 정해야 한다. 연결이 실패하면 데이터 전달 완료가 항상 보장되는 것도 아니다.

UDP는 데이터그램 단위로 보내고 자체적으로 도착·순서·재전송을 보장하지 않는다. 필요하면 응용이 보완한다. 낮은 지연이나 최신 정보가 중요하다고 해서 무조건 UDP를 고르지 말고, 손실 시 동작과 신뢰성 요구를 설명한다. 흐름 제어는 수신자가 감당하는 양을, 혼잡 제어는 네트워크가 감당하는 양을 고려한다.

TCP 연결 설정의 기본 예: 클라이언트 SYN(x) → 서버 SYN(y)+ACK(x+1) → 클라이언트 ACK(y+1). 서로의 초기 순서 번호를 확인하고 양방향 통신 상태를 준비한다. SYN은 연결 동기화 요청, ACK는 확인 응답이다. 세 메시지의 암기보다 ‘누가 무엇을 확인했는가’를 말한다.

기존 OSI·IP·ARP. 정의 확인: RFC 9293 TCP, RFC 768 UDP, RFC 826 ARP. 위 흐름과 예제는 학습용으로 구성했다.

문제 풀기

다른 네트워크의 서버로 보내는데 왜 공유기 MAC 주소가 필요한가요?

현재 링크에서 프레임을 전달할 직접 상대가 기본 게이트웨이이기 때문이다. 다음 링크에서는 그 링크에 맞는 전달이 이루어진다. 인터넷 전체 경로를 원격 서버 MAC 하나로 전달하는 것이 아니다.

면접 준비

TCP는 순서 있는 바이트 스트림의 신뢰성 있는 전달을 제공하고 UDP는 데이터그램을 보내지만 자체적으로 도착과 순서를 보장하지 않습니다. 데이터 누락을 허용할 수 있는지, 지연과 응용의 복구 요구가 무엇인지에 따라 선택하겠습니다. IP·MAC·포트는 각각 전달 범위와 통신 끝점을 구분하는 역할이 다릅니다.
TCP면 암호화까지 되는 건가요?

아니다. TCP의 신뢰성과 순서 보장은 기밀성과 별개다. HTTPS에서는 TLS가 암호화와 상대 인증 등을 담당한다. UDP 위에서도 별도 보안 프로토콜을 사용할 수 있다.

흐름 제어와 혼잡 제어는 왜 따로 필요한가요?

수신 버퍼가 넉넉해도 경로의 라우터나 링크가 과부하일 수 있고, 네트워크가 여유로워도 수신 프로그램이 느릴 수 있다. 제한이 생기는 위치가 다르므로 각각을 고려해야 한다.

순서대로 학습 · 원본 연결

24. 객체지향을 배운 뒤 가상 함수를 읽자

클래스·객체·상속을 먼저 이해하고, 다형성과 동적 바인딩을 실제 호출 결과로 설명한다.

데이터와 동작을 함께 묶는다

객체(object)는 상태와 동작을 함께 다루는 대상이다. 상태는 계좌의 잔액, 동작은 입금·출금처럼 생각한다. 클래스(class)는 어떤 상태와 동작을 갖는 객체를 만들지 정의한 타입이다. 같은 Account 클래스에서 만들어도 A계좌 잔액은 10, B계좌 잔액은 20으로 다를 수 있다. 메서드는 객체에 관련된 함수다.

캡슐화는 관련 상태와 동작을 묶고 접근 방식을 관리하는 것이다. 잔액을 아무 값으로 덮어쓰게 두지 않고 출금 메서드에서 잔액 부족을 검사한다. 추상화는 사용에 중요한 인터페이스를 드러내고 세부 구현을 감추는 것이다. ‘출금’ 동작을 쓰는 사람이 내부 저장 형식까지 알 필요는 없다. 둘은 관련되지만 같은 정의는 아니다.

상속과 다형성은 어떻게 연결될까

상속(inheritance)은 기존 타입을 바탕으로 새 타입을 정의하고 확장하는 방식이다. Dog는 Animal의 한 종류라는 관계로 생각할 수 있다. 다형성(polymorphism)은 공통 인터페이스로 서로 다른 타입을 다룰 때 각 타입에 맞는 동작을 수행하는 성질이다. 모든 Animal에 speak()를 요청하면서 Dog는 다른 방식으로 말하도록 할 수 있다.

// C++ 예제: 문법을 모두 암기하기보다 호출 대상을 추적한다.
struct Animal {
    virtual const char* speak() { return "animal"; }
    virtual ~Animal() = default;
};
struct Dog : Animal {
    const char* speak() override { return "dog"; }
};
Dog d;
Animal* p = &d;
// p->speak() 의 결과는 "dog"

struct는 타입을 정의한다. Dog : Animal은 상속, &d는 d의 주소, Animal*은 Animal을 가리키는 포인터 타입이다. ->는 포인터가 가리키는 객체의 멤버에 접근한다. 변수 p의 선언 타입은 Animal*이지만 실제 객체는 Dog다. virtual은 이런 호출에서 실제 객체 타입에 맞는 재정의를 선택하도록 한다. override는 올바르게 재정의했는지 컴파일러가 확인하게 한다. 소멸자 줄은 이 예의 기반 클래스 사용을 안전하게 하기 위한 선언이며 첫 회독에서는 speak 호출에 집중한다.

이 절은 원본 노트의 C++ 내용을 보존한 비교 학습이다. 아래 class·virtual·int&·STL은 C 문법이 아니다. C는 함수 이름에 따른 일반적인 오버로딩, 클래스 상속, 참조 매개변수를 제공하지 않는다. C 기반 객체 표현과 상태 조작은 구조체와 포인터·함수로 구분해서 설계한다.

오버로딩과 오버라이딩 · C++ 비교

오버로딩(overloading)은 같은 이름에 서로 다른 매개변수 목록을 두는 것이다. C++의 print(int), print(double)이 예다. 반환형만 달리해서 같은 매개변수 함수 둘을 구분할 수는 없다. 오버라이딩(overriding)은 상속받은 가상 함수를 파생 타입에 맞게 재정의하는 것이다. 단순히 같은 이름의 함수를 새로 만들었다고 모든 언어에서 항상 오버라이딩이 되는 것은 아니다.

바인딩(binding)은 이름·호출과 대상의 연결이다. 정적 바인딩은 실행 전 결정, 동적 바인딩은 실행 중 실제 객체 타입 등에 따라 결정한다. vtable은 가상 함수 호출을 구현하는 흔한 방식이지만 모든 컴파일러가 반드시 사용해야 하는 유일한 구현은 아니다.

값 전달·참조 전달

// C++: a는 처음에 1
void by_value(int x) { x = 9; }    // 복사된 x만 변경
void by_ref(int& x) { x = 9; }     // 호출자 변수의 별칭을 변경
// by_value(a) 이후 a=1, by_ref(a) 이후 a=9

참조 전달은 원본을 수정할 수 있다는 뜻이지 반드시 훼손한다는 뜻이 아니다. const 참조로 수정을 제한할 수도 있다. C에서 포인터 값을 전달하는 방식과 C++의 참조 매개변수는 구분한다. C에는 int& 참조 매개변수 문법이 없다.

원본 순서를 바꾸어 객체지향 기초를 먼저 배우고 바인딩, 참조·순수 가상 함수·STL로 연결했다.

원본 13·16쪽: 추상 클래스와 STL (C++ 전용)

일반적인 기반 클래스 포인터나 참조를 통한 가상 함수 호출은 실제 객체의 타입에 따라 오버라이딩한 함수를 선택한다. vtable은 널리 쓰이는 구현 방식이며 C++ 표준이 특정 테이블 구조를 강제하는 것은 아니다. 순수 가상 함수가 최종 재정의되지 않은 클래스는 추상 클래스이므로 직접 객체를 만들 수 없다. 추상 클래스의 포인터·참조는 사용할 수 있고, 파생 클래스가 필요한 순수 가상 함수를 구현하면 구체적인 객체를 만들 수 있다.

// C++ 예제: C 코드와 구분
struct Shape {
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
struct Square : Shape {
    double side;
    explicit Square(double s) : side(s) {}
    double area() const override { return side * side; }
};

STL의 기본 연결은 컨테이너·반복자·알고리즘이다. std::vector가 원소를 저장하고, begin()/end() 반복자가 처리 구간을 표현하며, std::sort가 그 구간을 정렬한다. 모든 컨테이너에서 모든 알고리즘을 그대로 사용할 수 있는 것은 아니다. 예를 들어 std::sort에는 임의 접근 반복자가 필요하다. 컨테이너 변경으로 반복자가 무효화될 수 있으므로 유효 조건도 확인한다.

문제 풀기

위 코드에서 포인터 p의 타입과 실제 객체 타입은 각각 무엇인가요?

p의 선언 타입은 Animal*, 실제 객체 d의 타입은 Dog다. 가상 함수 호출이므로 Dog::speak가 선택된다. ‘포인터가 Animal이니 항상 Animal 함수’라고 답하면 선언 타입과 실제 객체를 혼동한 것이다.

면접 준비

객체지향은 상태와 동작을 객체로 묶어 프로그램을 구성하는 방식입니다. 캡슐화로 상태 접근을 관리하고 추상화로 필요한 인터페이스를 제공합니다. 상속과 가상 함수 기반 다형성을 사용하면 공통 인터페이스 호출이 실제 객체 타입에 맞게 동작할 수 있습니다.
코드 재사용을 위해 항상 상속을 쓰면 좋나요?

아니다. ‘is-a’ 관계와 대체 가능성이 타당한지 봐야 한다. 단지 기능을 이용하는 관계라면 객체를 멤버로 갖고 동작을 위임하는 합성(composition)이 더 적절할 수 있다. 상속은 기반 타입 변경의 영향을 크게 받을 수도 있다.

순수 가상 함수와 일반 가상 함수는 어떻게 다른가요?

C++의 virtual void f() = 0;처럼 순수 가상 함수를 선언하면 해당 클래스는 추상 클래스가 되어 직접 객체를 만들 수 없다. 구체 타입으로 사용하려면 필요한 순수 가상 함수를 구현해야 한다. 일반 가상 함수는 기본 구현을 제공하며 재정의할 수 있다.

추상 클래스는 객체를 만들 수 없으니 포인터도 선언할 수 없나요?

포인터와 참조는 선언할 수 있다. 예를 들어 Square 객체를 Shape 참조로 다루고 가상 함수를 호출할 수 있다. 직접 만들 수 없는 것은 추상 클래스 자체의 객체다.

25. 데이터베이스: 표를 나누는 이유부터

키·함수 종속·정규화·JOIN·트랜잭션을 작은 데이터로 설명한다. 정의에 나오는 단어를 이해한 다음 정규형을 읽는다.

파일로 저장하면 되는데 왜 DBMS가 필요한가

파일에 기록하는 것만으로 데이터를 저장할 수는 있다. 여러 사용자의 동시 수정, 조건 검색, 제약 검사, 장애 복구 등을 프로그램마다 직접 구현하려면 복잡해진다. 데이터베이스는 조직된 데이터의 모음이고 DBMS는 이를 관리하는 소프트웨어다. 관계형 DB는 데이터를 테이블로 다루며 행(row/tuple)은 한 기록, 열(column/attribute)은 속성이다. 스키마는 테이블 구조와 제약 등의 정의다.

학번이름학과학과전화과목점수
101민수컴공1000OS90
101민수컴공1000DB85
102지수컴공1000OS95

예제 가정: 학생은 학과 하나에 속하고 학과마다 대표 전화 하나가 있으며 학생은 같은 과목을 한 번 수강한다. 실제 제도가 그렇다는 뜻이 아니라 종속성을 분석하기 위한 조건이다. 한 행은 (학번,과목)으로 구분된다.

키: 행을 구분하는 최소한의 근거

슈퍼키는 행을 유일하게 식별하는 속성 집합이다. 위에서 {학번,과목}도, {학번,과목,이름}도 슈퍼키다. 후보키는 속성을 더 빼면 유일성이 깨지는 최소 슈퍼키다. 여기서는 {학번,과목}이다. 후보키 하나를 대표로 고르면 기본키다. ‘최소’는 전체 후보키 중 열 수가 가장 적다는 뜻이 아니라 그 집합 안에서 더 뺄 수 없다는 뜻이다.

외래키는 다른 행의 적절한 유일 키를 참조하는 속성 집합이다. 예를 들어 수강.학번이 학생.학번을 참조한다. 기본키는 NULL과 중복을 허용하지 않으며, 외래키의 NULL 허용 여부는 별도 제약에 달린다. 존재하지 않는 학생 번호를 수강에 넣지 못하게 하는 것이 참조 무결성의 예다.

함수 종속: 같은 X면 Y도 같아야 한다

X→Y는 X값이 같은 행들은 Y값도 같아야 한다는 의미다. 위 가정에서 학번→이름, 학번→학과, 학과→학과전화, (학번,과목)→점수가 성립한다. 데이터 몇 줄이 우연히 그렇게 보이는 것이 아니라 관리할 데이터의 규칙으로 정해야 한다. X는 결정자, 후보키에 포함되는 속성은 주요 속성이라 부른다.

학과 전화가 바뀌면 여러 행을 바꿔야 하는 갱신 이상, 학생이 아직 수강하지 않으면 정보를 넣기 어려운 삽입 이상, 마지막 수강을 지우다 학생·학과 정보도 잃는 삭제 이상이 생길 수 있다.

분해 과정을 한 단계씩

  1. 1NF: 한 칸에서 모델이 정한 하나의 값을 다룬다. 과목 칸에 ‘OS,DB’ 목록을 넣었다면 수강 행을 나누는 식으로 정리한다. 위 표는 이미 그 형태다.
  2. 2NF: 후보키 일부에만 의존하는 비주요 속성을 분리한다. 이름·학과·학과전화는 (학번,과목) 중 학번만으로 결정되므로 학생(학번,이름,학과,학과전화)과 수강(학번,과목,점수)으로 나눈다.
  3. 3NF: 학생 표에서 학번→학과→학과전화의 관계를 보자. 학생(학번,이름,학과)과 학과(학과,학과전화)로 나누면 전화번호를 학과당 한 곳에서 관리한다.
학생: 학번·이름·학과수강: 학번·과목·점수학과: 학과·전화

분해 후 원래 정보를 정확히 복원할 수 있어야 하는 것이 무손실 조인이다. 아무렇게나 쪼개면 없던 행 조합이 생길 수 있다. 제약을 각 표에서 검사할 수 있는 종속성 보존도 고려한다.

심화: 3NF와 BCNF의 정확한 조건

비자명 함수 종속 X→A에서 ‘비자명’은 A가 X에 이미 포함된 속성이 아니라는 뜻이다. 3NF는 모든 이런 종속에 대해 X가 슈퍼키이거나 A가 주요 속성이어야 한다. BCNF는 모든 비자명 함수 종속의 결정자 X가 슈퍼키여야 한다. 그래서 BCNF가 더 강하다. 모든 3NF를 단순히 ‘비키끼리 종속 없음’이라고 정의하면 복합 후보키 사례를 놓친다. 4NF·5NF는 별도 다치·조인 종속을 다루며 기존 상세를 참고한다.

JOIN: 나눈 표를 필요할 때 연결한다

SELECT s.name, e.course, e.score
FROM Student AS s
JOIN Enrollment AS e ON s.id = e.student_id
WHERE e.score >= 90;

영어 열 이름을 쓰는 위 SQL은 Student=학생, Enrollment=수강이다. SELECT는 출력할 열, FROM은 대상 표, JOIN … ON은 연결 조건, WHERE는 선택할 행 조건이다. 위 데이터라면 (민수,OS,90), (지수,OS,95) 두 행이다. 출력 순서는 ORDER BY가 없으면 보장되지 않는다. INNER JOIN은 조건에 맞는 행만, LEFT JOIN은 왼쪽 행을 보존하며 짝이 없으면 오른쪽을 NULL로 채운다. JOIN이 항상 나쁜 연산은 아니다.

트랜잭션과 ACID

A에서 10을 빼 B에 더하는 이체가 중간에 실패하면 돈이 사라지면 안 된다. 트랜잭션은 이런 여러 조작을 하나의 논리적 작업으로 묶는다. 원자성(Atomicity)은 전부 반영 또는 전부 취소, 일관성(Consistency)은 정의한 무결성 규칙을 지키는 상태 변화, 격리성(Isolation)은 동시 작업의 간섭을 정해진 수준으로 제어, 지속성(Durability)은 커밋된 결과의 보존이다. 실제 격리 수준에 따라 허용하는 현상은 다르다.

COMMIT은 확정, ROLLBACK은 취소다. 일관성이 응용의 모든 현실적 오류를 자동으로 고친다는 뜻은 아니다. DB 잠금은 동시성 제어 수단 중 하나이며 MVCC처럼 여러 버전을 사용하는 방식도 있다.

인덱스는 검색을 돕는 보조 구조다. 조회가 빨라질 수 있지만 추가 공간과 삽입·갱신 시 유지 비용이 든다. 테이블 전체를 읽는 편이 유리한 쿼리도 있어 모든 열에 인덱스를 추가하는 것이 답은 아니다. B+tree는 16장의 범위 검색 설명과 연결된다.

원본 파일·스키마, 정규형·키·로킹. 연산 의미 확인: PostgreSQL JOIN 튜토리얼, 트랜잭션 튜토리얼. 학생 데이터와 문제는 새로 구성했다.

원본 16쪽: 스키마·제약·정규형·잠금의 연결

DB 설계는 요구 분석 → 개념 모델(ERD) → 논리 모델(관계·키·제약) → 물리 설계 → 구현으로 구분한다. ERD의 1:N 관계는 외래키로, N:M 관계는 연결 테이블로 표현할 수 있다. 도메인은 속성에 허용하는 값의 집합, 차수는 속성 수, 카디널리티는 튜플 수다. 기본키에는 NULL과 중복을 허용하지 않으며, 외래키는 허용된 NULL 또는 참조 가능한 키 값이어야 한다.

BCNF는 모든 비자명한 함수 종속 X→Y에서 X가 슈퍼키일 것을 요구한다. 4NF는 비자명한 다치 종속의 결정자가 슈퍼키일 것을 요구한다. 예를 들어 학생의 취미와 언어가 서로 독립이라면 학생·취미·언어를 한 표에 모두 조합해 저장할 때 중복이 늘어난다. 학생-취미, 학생-언어로 분해할 수 있다. 5NF는 후보키로부터 함의되지 않는 비자명한 조인 종속을 다룬다. 분해는 무손실 조인 등 성질을 검토해야 하며, 표를 많이 나누면 무조건 좋은 것은 아니다.

잠금 단위가 크면 관리할 잠금 수가 줄지만 서로 무관한 작업까지 기다릴 수 있다. 단위가 작으면 동시성을 높일 여지가 있으나 잠금 관리 비용이 커진다. DBMS와 격리 수준에 따라 잠금 외에 MVCC도 사용하므로 동시성 제어를 잠금 하나로만 설명하지 않는다.

26. 이산수학: 기호를 문장으로 읽기

집합·함수·논리·관계의 기호를 한국어 문장으로 풀고, 간단한 증명의 근거를 말한다.

집합은 ‘어떤 원소가 들어 있는가’

A={1,2}에서 1∈A는 1이 A의 원소라는 뜻이다. A⊆B는 A의 모든 원소가 B에도 들어 있다는 뜻이다. ∅는 원소가 없는 공집합이다. A∪B는 합집합, A∩B는 교집합이다. 집합은 순서·중복을 따로 세지 않아 {1,2}={2,1,1}이다. |A|는 원소 수다.

멱집합 P(A)는 모든 부분집합을 모은 집합이다. A={a,b}이면 P(A)={∅,{a},{b},{a,b}}다. 원소마다 포함·미포함 두 선택이 있어 n개 원소의 부분집합 수는 2ⁿ이다. ∅와 {∅}는 다르다. 전자는 원소가 0개, 후자는 공집합을 원소로 갖는 1개짜리 집합이다.

명제·조건·대우

명제는 참·거짓을 판단할 수 있는 문장이다. P∧Q는 둘 다 참, P∨Q는 적어도 하나가 참, ¬P는 P의 부정이다. P⇒Q는 ‘P이면 Q’다. P가 참인데 Q가 거짓인 경우에만 이 함의가 거짓이다. Q⇒P라는 역은 원래 명제와 다르고, ¬Q⇒¬P라는 대우는 원래 명제와 논리적으로 동치다.

‘4의 배수이면 짝수다’는 참. 역인 ‘짝수이면 4의 배수다’는 6 때문에 거짓. 대우 ‘짝수가 아니면 4의 배수가 아니다’는 참이다. 충분조건·필요조건을 말할 때 원래 화살표 방향을 먼저 적어 본다.

∀x는 ‘모든 x에 대해’, ∃x는 ‘어떤 x가 존재해’다. ‘모든 입력에서 성공’의 부정은 ‘모든 입력에서 실패’가 아니라 ‘실패하는 입력이 하나라도 존재’다. 알고리즘의 정확성 주장과 반례를 이해할 때 중요하다.

함수: 입력마다 출력 하나

f:X→Y에서 X는 정의역, Y는 공역, 실제 출력 f(X)는 치역이다. X={1,2}, Y={2,4,6}, f(x)=2x라면 치역은 {2,4}. 서로 다른 입력이 같은 출력으로 합쳐지지 않으면 단사, 공역의 모든 값을 실제 출력으로 만들 수 있으면 전사, 둘 다면 전단사다. 이 예는 단사지만 6을 만들지 못해 전사가 아니다.

Y 전체에서 원래 입력을 되찾는 역함수가 존재하려면 전단사여야 한다. 위 예는 공역을 {2,4}로 제한하면 역함수를 만들 수 있다. ‘단사이면 원래 공역 전체의 역함수가 있다’고 외우면 안 된다.

관계: 두 대상을 연결하는 조건

A×B는 가능한 순서쌍 전체이고 관계 R은 그 일부다. A={1,2}, B={a,b}이면 A×B={(1,a),(1,b),(2,a),(2,b)}다. 함수는 각 입력에 출력이 정확히 하나씩 있는 특별한 관계다.

성질뜻예
반사성모든 x에 xRxx≤x
대칭성xRy이면 yRx같은 나머지 관계
추이성xRy, yRz이면 xRzx≤y≤z이면 x≤z
반대칭성xRy와 yRx이면 x=y≤
비대칭성xRy이면 yRx가 아님<

반사·대칭·추이를 만족하면 동치관계다. 정수를 3으로 나눈 나머지가 같은 관계에서는 1,4,7이 같은 동치류에 속한다. 반사·반대칭·추이를 만족하는 관계는 부분순서다. 모든 두 원소가 비교 가능해야 한다는 조건은 따로 추가해야 한다.

수학적 귀납법: 도미노의 시작과 연결

1+…+n=n(n+1)/2를 n≥1에서 보이자. 기본 단계: n=1에서 1=1. 귀납 단계: k에서 맞다고 가정하면 k+1까지의 합은 k(k+1)/2+(k+1)=(k+1)(k+2)/2이므로 다음에서도 맞다. 기본 단계가 첫 도미노, 귀납 단계가 ‘하나가 쓰러지면 다음도 쓰러진다’는 연결이다. 몇 개의 숫자를 대입해 본 것만으로 모든 n에 대한 증명이 되지는 않는다.

귀류법은 결론의 부정을 가정하고 모순을 얻는 방식이다. 가장 큰 자연수 m이 존재한다고 가정하면 m+1이 더 크므로 모순이다. 집합 상등 A=B는 A⊆B와 B⊆A를 각각 증명할 수 있다.

원본 함수·집합·증명·관계를 기호 입문부터 재구성하고 명제·대우·양화사를 보충했다.

|P(A)|=2³=8. P(∅)={∅}로 원소 수는 1이다. ‘없음을 고르는 방법’ 한 가지가 있다. 2⁰=1과 일치한다.

함수는 정의역의 각 입력에 공역의 출력 하나를 대응시킵니다. 공역과 실제 치역은 다를 수 있고, 공역 전체에서 역함수를 가지려면 전단사여야 합니다. 보편적인 명제는 예를 몇 개 보는 것보다 귀납법이나 반례·논리 구조로 확인해야 합니다.
반대칭이면 대칭성이 성립하지 않는다는 뜻인가요?

아니다. 반대칭은 서로 다른 두 원소가 양방향으로 관계를 가지면 안 된다는 조건이다. 등호 관계는 대칭이면서 반대칭이다. ‘반대칭’과 ‘대칭의 부정’을 혼동하지 않는다.

‘모든 경우 O(n)이다’라는 주장에 반례 하나면 충분한가요?

어떤 보편 주장인지 정확히 해야 한다. ‘어떤 입력에서도 비용이 특정 상한 이내’라는 주장에는 그 상한을 어기는 입력이 반례다. 그러나 점근적 O(n)은 충분히 큰 n과 상수의 존재를 말하므로, 작은 n 하나에서 느렸다는 실측만으로 깨지지는 않는다. 입력 집합에 따른 비용 증가를 구분한다.

27. 남은 원본 범위와 자주 혼동하는 연결

앞 장에서 깊이 다루지 않은 원본 항목을 위치와 의미까지 알고, 모르는 용어를 다른 개념과 섞지 않는다. 자세한 조건·변형은 하단 원본 대응표에서 찾는다.

검색·정렬의 변형

Trie는 문자열의 문자 등 키의 조각을 따라 내려가는 구조다. cat과 car는 c→a 경로를 공유하고 다음 t/r에서 갈라진다. 접두사 검색에 자연스럽다. 한 단계 자식 접근 비용을 일정하게 보면 길이 L의 키 검색은 O(L)이다. 키 개수 n에 대한 O(log n)과 입력 기준부터 다르다.

보간 탐색은 정렬된 수치 키의 값 분포로 위치를 추정한다. 균등 분포 등 조건에서 평균 O(log log n)을 기대할 수 있지만 최악은 O(n)이다. 셸 정렬은 간격을 둔 삽입 정렬을 하고 간격을 줄여 마지막 1로 마무리한다. 성능은 간격 수열에 따라 달라진다. MSD 기수 정렬은 높은 자리부터 그룹을 나누고, LSD는 낮은 자리부터 안정 정렬을 반복한다.

외부 정렬은 데이터가 RAM에 다 들어가지 않을 때 저장장치 I/O를 고려하는 정렬이다. 큰 파일을 메모리에 들어갈 조각으로 정렬해 저장하고, 정렬된 여러 조각의 맨 앞을 보며 병합할 수 있다. 정렬된 조각을 run이라 부른다. CPU 비교 수뿐 아니라 블록을 얼마나 읽고 쓰는지가 중요하다.

해시·암호화·서명은 목적부터 구분

암호화는 키를 가진 쪽이 복호화할 수 있도록 내용을 숨기는 데 사용한다. 대칭키 방식은 공유한 비밀키를 쓰고, 공개키 방식은 공개키·개인키 쌍을 사용한다. 암호학적 해시는 메시지에서 고정 길이 요약값을 만들며 역상·충돌 공격에 대한 저항성 등이 요구된다. 일반적으로 원문 복원 기능을 제공하지 않는다.

디지털 서명은 개인키로 서명하고 공개키로 검증하여 메시지 출처·변경 여부를 검증하는 데 사용한다. 서명만으로 메시지 내용이 숨겨지는 것은 아니다. 서명을 단순히 ‘개인키로 암호화’라고 일반화하지 않는다. 키 합의는 양측이 공유 비밀을 정하는 절차이고, 인증 없는 키 합의만으로 상대의 신원까지 보장되지는 않는다.

기밀성은 허가되지 않은 쪽에서 내용을 읽지 못하게, 무결성은 무단 변경을 탐지·방지하게, 가용성은 필요할 때 사용할 수 있게 하는 목표다. 해시값만 메시지 옆에 붙이면 공격자가 둘 다 바꿀 수 있으므로 인증까지 자동 보장하지 않는다. 비밀번호 저장용 해싱은 빠른 일반 해시와 목적이 다르다.

장치·파일·스키마

인터럽트는 장치 등의 사건에 대응하도록 CPU에 알리는 메커니즘이다. 폴링은 소프트웨어가 상태를 반복 확인하는 방식이다. 대기 부하·응답 지연·사건 빈도에 따른 절충이 있다. daisy chain은 장치들을 따라 승인 신호를 전달해 인터럽트 우선순위를 정하는 하드웨어 방식의 예다. 네트워크 패킷의 경로 선택과 같은 뜻이 아니다.

HDD 스케줄링의 SSTF는 현재 헤드에서 가까운 요청부터, SCAN은 한 방향으로 이동하다 끝에서 방향을 바꾸는 방식이다. SSD는 움직이는 헤드가 없으므로 같은 기계적 모델을 그대로 적용하지 않는다.

파일 시스템은 이름·디렉터리·저장 위치·접근 권한 등을 관리한다. DB의 외부 스키마는 사용자별 뷰, 개념 스키마는 전체 논리 구조, 내부 스키마는 물리 저장 관점이다. DDL은 구조 정의, DML은 데이터 조회·변경, DCL은 권한 제어에 관한 분류다. 관계대수는 선택·투영·조인 같은 연산으로 질의를 표현하고, 관계해석은 결과가 만족할 조건으로 표현한다. 관계대수의 selection은 행 선택, projection은 열 선택이다.

분산 처리와 동적 계획법: 새로 보충하는 연결

분산 시스템은 여러 컴퓨터가 네트워크로 협력하는 시스템이다. 한 컴퓨터 내부 스레드와 달리 통신 지연과 일부 노드만 실패하는 부분 장애를 고려해야 한다. 컴퓨터 수를 늘린다고 항상 처리 시간이 줄거나 가용성이 높아지는 것은 아니다.

동적 계획법(DP)은 겹치는 부분문제의 결과를 저장해 재사용하는 설계법이다. 피보나치 F(n)=F(n−1)+F(n−2)를 그대로 재귀 계산하면 같은 F(k)를 반복 계산한다. F(0)=0,F(1)=1에서 1,2,3,5…를 차례로 저장하면 n번째까지 O(n)에 계산할 수 있다. 직전 두 값만 필요하면 추가 공간 O(1)도 가능하다. 최적화 문제에서는 최적 부분구조 등 DP로 풀 수 있는 근거와 상태·전이를 설명해야 한다.

심화 자료로 넘어갈 기준

Red-Black 삽입의 각 경우, B-tree 분할·병합, Borůvka, 4NF·5NF, 기수별 상세 복잡도는 원본 상세를 보존했다. 먼저 ‘무엇을 해결하는가’와 앞 장의 기본 예제를 설명한 후 확장한다. 관심 연구실이나 공식 안내에서 해당 영역을 강조하면 우선순위를 올린다. 본 교재의 확장 분류가 실제 시험에서 제외된다는 뜻은 아니다.

문제 풀기

파일 내용과 해시값을 함께 받았다. 이것만으로 발신자가 진짜인지 알 수 있나요?

아니다. 믿을 수 있는 경로의 기준 해시인지, 인증된 MAC(메시지 인증 코드)이나 서명 검증이 있는지 등이 필요하다. 공격자가 파일과 해시를 모두 바꾸면 단순 재계산 비교만으로 발신자를 인증할 수 없다. 이 MAC은 네트워크 인터페이스의 MAC 주소와 다른 약어다.

면접 준비

익숙한 이름이 비슷해도 목적과 비용 기준을 먼저 구분하겠습니다. 예를 들어 해시 요약은 원문 복호화가 목적이 아니고, 디지털 서명은 내용의 기밀성을 자동으로 제공하지 않습니다. 자료구조도 키 개수·키 길이·블록 I/O 중 무엇을 비용으로 보는지에 따라 선택이 달라집니다.
메모이제이션을 사용한 재귀는 추가 공간 O(1)인가요?

일반적으로 아니다. 저장한 부분문제 결과와 호출 스택 공간을 모두 본다. 피보나치를 n개 상태로 저장하면 O(n) 공간이다. 직전 두 값만 쓰는 반복형 구현과는 별도다.

28. 내 연구를 컴퓨터공학 질문으로 연결하기

연구 경험을 말할 때 정의·실험 조건·관측 결과·한계를 구분한다. 학업계획서를 작성하는 장은 아니며, 연구에서 전공 질문으로 이어지는 구술 연습이다.

현재 작업 공간은 로봇 형상·보행 학습 연구와 관련되어 있다. 아래는 그 맥락을 활용한 연습 질문과 설명 틀이다. 본인의 실제 사용 알고리즘이나 성과 수치를 대신 확정하지 않는다. ‘제가 구현했습니다’와 ‘기존 구현을 사용해 평가했습니다’도 본인의 역할에 맞게 구분한다.

연구 설명을 네 덩어리로 준비한다

①무슨 문제인가: 비교할 대상·목표. ②어떤 방법인가: 입력·출력·알고리즘·본인의 기여. ③어떻게 평가했나: 비교 기준·동일 조건·평가 지표. ④무엇을 아직 모르는가: 일반화 범위·실물 검증·추가 실험. 이 네 부분이 연결되어야 꼬리질문에서 설명이 흔들리지 않는다.

연습 틀: “제가 다루는 문제는 [문제]입니다. [입력]을 이용해 [출력]을 얻고, [방법]으로 비교했습니다. 성능은 [같은 평가 조건]에서 [측정 지표]로 확인했습니다. 다만 [아직 검증하지 못한 조건]은 남아 있어 [추가 검증]이 필요합니다.” 대괄호는 실제 기록으로 채우며 관측하지 않은 성과는 넣지 않는다.

강화학습을 말한다면 먼저 정의할 것

강화학습은 환경과 상호작용하며 얻는 보상에 따라 행동 전략을 개선하는 문제를 다룬다. 상태(state)는 환경의 상황, 관측(observation)은 에이전트가 받는 정보, 행동(action)은 선택하는 제어, 정책(policy)은 관측·상태 등에 따라 행동을 정하는 규칙이다. 즉시 보상과 미래 보상을 합친 누적 보상은 다르다. 할인율 γ는 미래 보상을 현재 목표에서 얼마나 반영할지 조절한다.

지도학습은 보통 입력과 목표 정답의 쌍으로 예측을 학습한다. 강화학습에서는 행동이 이후 데이터와 보상에 영향을 주고 결과가 늦게 드러날 수 있다. ‘정답이 없으니 아무 기준도 없다’는 뜻은 아니다. 보상 설계가 곧 목적을 완전히 대변하는지도 검토해야 한다.

보상·실제 지표·일반화를 분리한다

높은 보상이 실제로 더 빠른 이동이나 더 안정적인 보행과 같은 뜻인지 확인해야 한다. 속도만 보면 넘어지기 직전의 짧은 돌진을 좋게 평가할 수 있어 평가 구간·낙상·추종 오차 등의 정의가 중요하다. 특정 실험에서 그렇게 나타났다고 주장하려면 본인의 기록이 필요하다.

여러 설계를 비교할 때 학습 예산·평가 시간·초기 조건·명령·환경 조건을 통제하지 않으면 다른 요인이 결과에 섞인다. 난수 시드(seed)를 여러 개 사용하고 평균뿐 아니라 변동도 확인하는 이유는 한 번의 우연을 일반 성능으로 오해하지 않기 위해서다. 같은 데이터를 반복 보며 설계를 골랐다면 별도 최종 평가 조건이 필요할 수 있다.
